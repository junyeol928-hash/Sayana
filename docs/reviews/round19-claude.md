## 4. SOTD に届かない理由(効き目の大きい順)

Brilliant や Execute Program のような受賞級の学習サイトと並べたとき、負けるのは「問いに触れた瞬間の手触り」。この道場は問いの数と中身では並んだ。ところが、問いの部品(コードの組み・選択肢の形・間違えたときの反応)が、ホームとレッスンの冒頭で作り込んだ品質に届いていない。上の 5 件は Design・Usability・L の「一部」を直接消す。

### 1. 「手を止めて」のコードが字下げを失い、選択肢もクイズと別の部品
- 軸・項目: Design D4・D5、Usability U3・U4、学びやすさ L4
- 画面: m-check・m-check-answer(`body ->` の次の `System.out.println("[偽] " +` が 0 桁目から始まる)、撮り足しの `x-check2.jpg`(`OrderService(MailSender mail) {` の次の `this.mail = mail; }` がクラスの直下の文に見える)、`x-check-dark.jpg`(`return new` の次の `SmtpMailSender(...)` が 0 桁目)
- 問題: 手を止めては「構造を読んで予想する」問いなのに、スマホでは折り返した続きが行頭から始まり、行番号もないので、本物の行と折り返しの区別がつかない。原因は 2 つ。`decorate()` の `code-lines` を付ける選択子(app.js 1900 行 `.quiz-q .md pre, .q-explain pre, .review-quiz pre, .quiz-answer pre, .reading-answer pre`)に `.check pre` が入っていないこと、`.check pre { white-space: pre-wrap; overflow-wrap: break-word }` で素のまま折り返していること。選択肢は `button.choice` で、クイズ・復習・読解の左の丸(正解は藍の丸にレ点、誤答は朱の枠に ×)がなく、答えたあとは小さな文字の札だけ。押すとボタンが `disabled` になり、フォーカスが `<body>` に落ち、`.check-explain` に `aria-live` もないので、読み上げでは何も起きない
- 直し方:
  - app.js 1900 行の選択子に `.check pre, .check-explain pre` を足す(行番号・続きの縦線・字下げ 8 文字止め・400px 以下で半分が、クイズと同じに効く)。app.css 913 行の `.check pre` からは `white-space` と `overflow-wrap` を外し、`.md pre.code-lines` と同じ `padding-left: 0` にする
  - `checkHtml`(ContentRepository 289 行)の各ボタンの先頭に `<span class="choice-dot" aria-hidden="true"></span>` を足し、CSS で `.choice input` と同じ 22px の丸を描く。`.is-answer` は藍の丸にレ点、`.is-wrong` は朱の枠に ×(既存の `.choice.is-answer input` の規則を `.choice-dot` にも当てる)
  - `bindChecks` で答えたら `ex.tabIndex = -1; ex.focus({ preventScroll: true })`。`.check-explain` に `aria-live="polite"`。選択肢の group は `aria-label="選択肢"` ではなく `aria-labelledby` で `.check-q` に結ぶ

### 2. 復習で間違えても運針と見出しが変わらず、「次回」の札がボタンに見える
- 軸・項目: Usability U5・U4、学びやすさ L3、Creativity C1
- 画面: m-review-answer、撮り足しの `x-review-after-top.jpg`(誤答のあとも上が「残り 25 問」「3 日後の復習(4 回のうち 2 回目)・卒業まで あと 3 回」)
- 問題: `reviewAnswer` は誤答で `stage: 0` に戻すが、画面は `sewStitch`(正解のときだけ)しか呼ばず、上の運針・字幕・残りの数を描き直さない。下の「次回: 1日後に復習」と上の「2 回目・あと 3 回」が同じ画面で食い違う。「やり直し」がこの道場でいちばん効く手応えなのに、運針の比喩がそこで黙る。運針はページの見出し(「残り 24 問」の下)にあり、今日の進み具合の線にも読める。`.review-note`(app.css 838 行)は `--surface-2` の塗りと角 8px で、主ボタンの左に同じ高さで並び、押せない札がボタンに見える。解説が長いので、選んだ誤答(「× あなたの答え」)は画面の上に外れる
- 直し方:
  - 誤答のときは運針を描き直す: 縫えていた目を針穴の点線に戻し、朱の玉結びを 1 目めへ(160ms の ease-out の色の変化だけ。動きの種類は増やさない)。字幕は「ほどけた。明日、1 回目からもう一度」。正解のときも含め、答えたら「残り n 問」と「今日 n 問済み」を描き直す
  - 運針は問いのカードの上端(問いの文の上)へ移す。見出しの行は「残り 24 問・今日 3 / 10」(区切りまでの数)にする
  - `.review-note` は `background: none; padding: 0; color: var(--ink-muted)` の 14px の文字にし、「次は 1 日後」と短くする(または運針の字幕に入れる)
  - 採点したら、選んだ選択肢の上端が画面の上から 120px に来るように送り、判定の行(`tabindex="-1"`)にフォーカスを移す

### 3. 実行結果がまだ二重の箱で、出力が「-」1 字の行と語の途中で割れる
- 軸・項目: Design D3・D5、Usability U3
- 画面: m-sample-result(暗い表示の撮り足し `x-sample-result-dark.jpg` も同じ)
- 問題: 「沈んだ面+左の藍線」の中に、さらに暗い箱がある。出力の 1 行は半角約 33 字で、真上のサンプルのコード(全幅の帯)より細い。`line-break: strict` は和文の語の途中の折り返しを止めないので、design.md 139 行の「語の途中では割らない」は実現していない。「--- ① 手動で組み立て(素の Java の DI)--」の次に「-」だけの行が残る
- 直し方:
  - 760px 以下は `.sample-result .run-result { background: none; padding: 0; border-left: 0; }` とし、`.console` 自体を真上のサンプルと同じ全幅の暗い帯(`margin: 0 -20px; border-radius: 0`)にして、左に 3px の藍(例外は朱)の線を引く。「実行結果」の字は帯の上の 13px の見出しにする
  - `.sample-result .console` に `word-break: auto-phrase`(Chromium 119 以降、`lang="ja"`)を足す。Safari のために、`sampleResult()` で出力の各行を見出しの `phraseWrap` と同じ Intl.Segmenter で語の箱に分ける。記号の連なり `/[-─=]{2,}/` は `white-space: nowrap` の span で包む
  - 教材の区切りから後ろの「---」を外す(「--- ① 手動で組み立て(素の Java の DI)」)

### 4. 復習の解説が 1 行 約 17 字の 1 段落のまま
- 軸・項目: 学びやすさ L4、Usability U3、Design D3
- 画面: m-review-answer
- 問題: カード(枠 1px+余白 14px)の中に解説の箱(左線 3px+余白 14px)があり、本文は画面の端から約 54px 内側から始まる。9 行に 14 個のチップ、`case` と `3` が行をまたぐ。switch のどこへ飛んでどこで抜けるかという順番の話を、地の文で追わせている
- 直し方: 760px 以下は `.review-quiz { border: 0; padding: 0; background: none; }` にして、レッスンのクイズと同じく地の上に問いを置く(解説の箱が画面の左右 20px まで広がり、1 行 約 20 字)。`:not(pre) > code` のうち 12 字以下は `white-space: nowrap`。教材の解説は「たどる順」の番号付き 3 行(1. `case 2` に飛ぶ → B / 2. `break` がないので `case 3` へ → C / 3. `break` で抜ける。`default` の D は出ない)に分ける

### 5. 「左に藍線の面」が 5 つの意味に使われ、手を止めてが道場の顔にならない
- 軸・項目: Creativity C3・C1、Design D4
- 画面: m-check、m-sample-result、m-quiz-inline、m-lesson-atwork、m-terms
- 問題: 手を止めて・実行結果・解説・仕事のコードの行の説明・用語の説明が、どれも「沈んだ面に左 3px の藍の線」。読む流れの中で手を止めては、本文の注意書きと同じ顔をしている。本文の中に 164 回出る、この道場でいちばん回数の多い「間」なのに、運針も札も軸も使っていない。SOTD の審査員は「その画面にしかない形」を探すので、ここが既視感になる
- 直し方: 手を止めては左線をやめ、刺し子の枠(`--stitch` の破線 2px を四辺に、角 14px)で囲み、左上に部の札と同じ縦書きの小さな札「手を止めて」(藍地に白、12px、`writing-mode: vertical-rl`)を下げる。枠の上端に運針の針目を 1 本置き、正解したら針目が糸になる(既存の「縫う」240ms。動きの種類は増やさない)。間違えたら針穴のまま。左線の面は「解説」と「行の説明」だけに残し、design.md の「区切りは刺し子」に手を止めてを足す

### 6. 選んだ誤答に向けた 1 文がない
- 軸・項目: 学びやすさ L3
- 画面: 撮り足しの `y-if-check-top.jpg`(java-if の手を止めて。A を選ぶと「× 不正解」の下は「B はインデントのとおりに読んだ答え」で、A の話がない)、m-review-answer、m-quiz-inline
- 問題: 教材の解説は誤答の理由を多く書いている(java-collections の「C は添字を 1 から数えた答え」など)。ただ、1 段落に全部入っていて、自分の誤答の文を探すことになる。書かれていない誤答もある
- 直し方: checks.yml の `choices` に誤答ごとの `why`(1 文)を書けるようにし、「× あなたの答え」の真下に 14px で出す。手を止めての 164 問は解説の中に既に理由がある問が多いので、抜き出しから始める(java-if の A: 「A は x が 10 を超えるとき。x は -1 なので外側の if で止まる」)

### 7. 手を止めてが「説明を読んだ直後」に置かれ、本文の山場では答えが先に見える。半分が 2 択
- 軸・項目: 学びやすさ L1・L2
- 画面: m-check(spring-di の 1 問目は、20 行上のコードの文字列を「送信したつもり」から「偽」に替えただけ)、教材 `01-java-if/lesson.md` 59〜65 行
- 問題: どの問いも `after:`(節の終わり)にしか置けない。java-if の本文は「インデントだけ見ると…に見えますが、実行すると……」と、そのまま予想の問いになる所で、答え(「5以下」と出た)を次の行で見せてしまい、手を止めては同じ現象を節の終わりでもう一度聞く。読んだ直後の再認で、予想して外す体験(前もって解く効き目)にならない。164 問のうち 85 問が 2 択で、それが復習にも入る(当てずっぽうで 4 回続けて正解する確率は 6%)
- 直し方: checks.yml に `before:`(段落の書き出しの文字列)を足し、説明の前に問いを置けるようにする。java-if は 59 行の「実行すると……」の直後に置き、65 行の答えの段落は解説の欄へ移す。spring-di は「IoC コンテナに組み立てを任せる」の前に「コンテナでもコンストラクタは呼ばれる?」を置く(サンプルの問いと重なる)。2 択は、3 つ目のもっともらしい誤答を足すか、復習には入れない

### 8. PC の復習: 「答える」が折り目の下、コードに行番号がない
- 軸・項目: Usability U1、Design D4
- 画面: pc-review

- 直し方: 1200px 以上は問いのカードを 2 列(左 7fr にコード、右 5fr に選択肢と「答える」)にする。選択肢の余白を 10px・間 6px に詰める。コードに `code-lines` を付ける

### 9. 10 問の区切りが汎用の吹き出しで、ホームの目安も古いまま
- 軸・項目: Creativity C1・C3、学びやすさ L5
