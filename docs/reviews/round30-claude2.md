### 1. スマホのサンプルの実行時例外が、サーモン色の箱で理由が右の外にある
- 軸・項目: Design D2(学びやすさ L3)
- 画面: スマホの java-variables の「予想: 最後の memo.length() の行では、何が起きる?」を開いた結果(撮り足し m-variables-exception-light・-dark)
- 問題: 29 回目の直しは PC の `.sample-out pre.exception, #playground-out pre.exception` だけに当てた。そのためスマホの `.sample-result pre.exception` には、いまも `.exception { background: var(--ng-soft) }` と `white-space: pre` が効く。390px で 885px の 1 行が 387px の箱に入り、「例外が発生しました: java.lang.NullPointerExcepti」で切れる。予想の答えの中心(「because "memo" is null」)が見えない。スマホは平日の主な読む端末
- 直し方:
  - `app.css` の 1002・1003 行の対象に `.sample .sample-result pre.exception` を足す(`background: var(--code-bg); color: var(--code-ink); white-space: pre-wrap; overflow-wrap: anywhere;`)。1054・1055 行の全幅と朱の左線はそのまま使える
  - 見た目はスマホの出力の帯と同じになる。design.md の「スマホは箱の中に箱を作らず」に戻る
  - `./mvnw -q compile exec:java` で `m/` を作り直し、撮影に m-sample-exception(明るい・暗い表示)を足す

### 2. コメントの真下の代入文で落ちると、行番号が指示のコメントの行を指す
- 軸・項目: 学びやすさ L3(Content N1 の隣)
- 画面: PC の java-arrays「配列を作って中身を見る」を sales[5] にした結果(撮り足し pc-break-java-arrays。「at (11行目)」で、11 行目は「// ここを sales[5] にすると? 例外メッセージを読んでみよう」)。java-encapsulation「防御的コピーあり/なしの比較」も 20 行目 → 「19行目」
- 問題: 代入・複合代入・`++` の式のスニペットでは、JShell のスタックトレースの行がコメントを除いた式の頭から数えられる。一方 `JShellRunner` は、コメントの頭(`offset`)を 1 行目として足す。メソッド呼び出しの式・宣言・if・for ではコメントも数えられるので合う。今回、行末のコメントを上の行へ移した(93f8293)ことで、ちょうど誘いの行の真下に代入文が来た
- 直し方:
  - `Evaluation.evaluate` で、`whole.stripLeading()` の代わりに、頭の空白と `//`・`/* */` のコメントを全部除いてから `eval` する。除いた分だけ `offset` を進めて `lineOf(offset)` を取る。コメントは評価に影響しないので、どのスニペットの種類でも 1 行目がコードの行になる
  - `JShellRunnerTest` に「`// c` の下の `a[5] = 1;`」「2 行のコメントの下の `x += 1 / y;`」「コメントの下の `a[5]++;`」を足す

### 3. 例外の 1 行目の朱が、折り返しの途中で切れる
