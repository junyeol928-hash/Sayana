## 4. SOTD に届かない理由(効き目の大きい順)

### 1. 復習の画面に道場の顔がなく、判定の部品もレッスンと違う
- 軸・項目: Creativity C1・C3、Design D4
- 画面: m-review、m-review-answer、pc-review
- 問題: 復習はホームの主役の次に毎日開く画面(25 問 約 9 分)なのに、白いカードとラジオの一般的なクイズで、藍・軸・運針のどれもない。「段階 2 / 4」は丸い錠剤のバッジ。答えたあとは朱の 36px の「不正解」(アイコンなし。正解なら `.correct .q-mark { color: var(--ok) }` の緑)が画面でいちばん大きな文字になり、レッスンのクイズの「× 不正解」(14px・線のアイコン)・藍の「✓ 正解」と別の部品。「正解: BC」で正解の全文を繰り返す(design.md の「解説の箱では正解の全文を繰り返さない」に反する)。答えたあとも薄い「答える」が残る
- 直し方:
  - 「段階 2 / 4」の錠剤を、1・3・7・14 日の 4 目の運針に替える(縫えた目は藍の糸、今回の目に朱の玉結び、まだの目は針穴)。下に「3 日後の復習(4 回のうち 2 回目)」。正解したら今回の目が糸になる(染み込みと同じ 560ms・`cubic-bezier(.22,1,.36,1)`)。4 目そろって卒業したら、そのレッスンのマスが深まる染み込みを 1 回
  - 判定はレッスンのクイズと同じ部品(`.q-explain` の `q-mark`: 14px、「✓ 正解」藍/「× 不正解」朱、線のアイコン付き)にし、復習から `.q-mark.big` と緑を外す。「正解: …」の行は消す(選択肢に札が付くので)
  - 答えたら `button[type=submit]` を `hidden` に(読解の `lockAnswer` と同じ)
  - PC の題を「復習」に(`templates/review.html` の h1)

### 2. 実行結果が三重の箱で、緑が 3 つ目の色になり、出力が語の中で割れる
- 軸・項目: Design D2・D3、Usability U3
- 画面: m-sample-result
- 問題: 地 → 緑の面(`.run-result.status-ok`)→ 暗い pre の三重で、出力の 1 行が半角でおよそ 35 字。`overflow-wrap: anywhere` のため「--- ① 手動で組み立て(素の Java の DI)---」の「---」が「-」と「--」に割れ、「コー/ヒー豆」「ドリッ/プバッグ」と語の途中で折れる。緑の面は画面でいちばん大きな色面で、「有彩色は 1 画面で藍と朱まで」の外
- 直し方: 760px 以下は緑の面をやめ、「実行結果」の小見出しの直下に、サンプルのコードと同じ全幅の暗い帯で出力を置く。成功は帯の左に 3px の藍の線、例外は朱の線と「× 例外」の文字。`.sample-result .console` を `overflow-wrap: break-word; line-break: strict;` にする。教材の出力の区切りは「① 手動で組み立て(素の Java の DI)」のように前後の「---」を外す。design.md の「緑の面に出力」の一文も直す

### 3. 復習で、答える前に出どころのレッスン名が見える
- 軸・項目: 学びやすさ L2(Usability)、Content N4
- 画面: m-review(「条件分岐」)、pc-review(「DIとIoCコンテナ」)
- 問題: 混ぜて出す効き目は「どの知識を使う問題かを自分で見分ける」ところにある。答える前にレッスン名がリンクで見えると、見分ける前に答えの範囲が分かる。リードの「選択肢の並びも毎回変わります」は、同じ日は同じ並びという実装と食い違う
- 直し方: 答える前の行は「残り 24 問(今日 n 問済み)」と指摘 1 の運針だけにする。レッスン名は答えたあと、判定の下に「出どころ: 条件分岐 → 読み直す」で出す(PC も同じ)。リードは「いろいろなレッスンの問題を混ぜて出します。選択肢の並びは日ごとに変わります」

### 4. 復習の解説が細切れで、順番の話を 1 段落で読ませている
- 軸・項目: 学びやすさ L4、Usability U3、Design D3
- 画面: m-review-answer
- 問題: カードの中に解説の箱があり、本文は画面の左右とも約 56px 内側から始まって 1 行約 16 字。9 行に 14 個のコードのチップが並び、「case 3」が「case」と「3」に割れて行をまたぐ。switch がどこへ飛んでどこで抜けるかという順番の話を、地の文 1 段落でたどらせている
- 直し方: スマホの `.review-quiz` は枠と内側の余白をなくし(またはカードの余白を 12px に)、解説の箱を画面の左右 20px まで広げる。12 字以下のインラインコードは `white-space: nowrap`。教材の解説に「たどる順」の箇条書きを使い、この問題なら「1. case 2 に飛ぶ → B」「2. break がないので case 3 へ → C」「3. break で抜ける(default の D は出ない)」の 3 行、続けて誤答ごとに 1 行(「B だけ → アロー構文 case 2 -> のとき」)

### 5. スマホのサンプルのコードが右で切れ、続きがあると分からない
- 軸・項目: Usability U3、学びやすさ L4
- 画面: m-sample-closed
- 問題: 長い行が「annotation」「body」「+ b」で画面の端に切れ、フェードも案内もない。スマホではサンプルを動かせない(見出しも「サンプルを見る」)ので、「書き写す・実行するので折り返さない」の理由がスマホには当てはまらない。予想させたい `return` の文やコメントほど右で切れている
- 直し方: 760px 以下はサンプルも仕事のコードと同じ組み(折り返し・行番号・続きの行の縦線・字下げ 8 文字止め・400px 以下で半分)にする。PC は今のまま横スクロール。最低限でも、はみ出した `pre` の右端に `watchOverflow` のフェードを付ける

### 6. 「予想したら」が受け身で、予想を形に残さない
- 軸・項目: 学びやすさ L1、Creativity C1
- 画面: m-sample-closed(閉じた欄は撮影の外)、m-sample-result
- 問題: 欄の名前が予想を促すだけで、何を予想するかがない。開けば全部見える。リードが言う「コンテナもコンストラクタを呼んでいる」の根拠になる行(① と ② の両方に出る「OrderService を new した」)にも印がない
- 直し方: 教材の sample に `predict:`(問い 1 行と選択肢 2〜3 個)を足し、欄の上に「② のコンテナ版でも『OrderService を new した』は出る?」と錠剤のトグル [出る] [出ない] を置く。選ぶまで「実行結果を見る」は弱い色、選んだら開いて、選んだ札に「✓ 予想どおり」「× 予想と違う」。出力の答えに当たる行には、仕事のコードと同じ藍の行番号の札を付ける

### 7. 初めて開いた人に、保存の途中の文と緑の点が見える
- 軸・項目: Usability U5、Design D2
- 画面: m-home-light(「保存の準備中。次に電波のある所で開くと、電波なしで読めます」)、m-home-dark(緑の点「保存済み(全 55 レッスン)。図は次に電波のある所で開くと保存」)
- 問題: Awwwards の審査員はまっさらなブラウザで開くので、最初に見るのはこの状態。ヒーローと地図の間に 2 行の注記が入り、ヘッダーの「保存済み」が消える(レッスンの撮影では出ている)。電波がある場面で「次に電波のある所で」は合わない。`.save-state.ok::before` が `--ok` の緑
- 直し方: 電波があって保存が進んでいる間は、ヒーローに文を出さず、ヘッダーの印を「保存中」(12px の円の縁を藍の線が縫い進むように埋める)にする。図だけが残っているときは文を出さず、裏で取る。文にするのは失敗・一部だけ・電波なしで欠けているときだけ。`.save-state.ok::before` は `var(--accent)`。電波があるときの文言は「図を保存しています」

### 8. PC の復習: 主ボタンが折り目の下で、言葉がそろわない
- 軸・項目: Usability U1、Content N4、Design D4
- 画面: pc-review
- 問題: 1440×900 で「答える」の上端しか見えない。前置きが 3 行(間隔の説明)。題が「復習キュー」で、上のメニューとスマホは「復習」。「段階 1/4」「つまずき 1」の錠剤

### 9. 最初の 5 秒に、この道場だけの動きの見せ場がない
- 軸・項目: Creativity C4・C2(SOTD の物差しで。項目は満たしている)
- 画面: m-home-light、pc-dashboard(静止画なので実装から判断)
- 問題: 署名の動きは押したボタンのそばの 28px の染み込みと、段の帯の縫い進む線だけ。ホームを開いたときに動くのは、前より深まったマスだけで、ふだんは何も起きない。SOTD の審査員は最初の画面の手触りで覚えるので、ほかの SOTD と並ぶと静かすぎる
- 直し方: ホームのヒーローの運針を、その日はじめて開いたときに 1 回だけ「縫う」。済んだ段の糸を左から順に伸ばし(1 本 240ms、120ms ずつずらす、`cubic-bezier(.22,1,.36,1)`)、最後に朱の玉結びを 1 回だけ染み込ませる。合計 1 秒以内、`prefers-reduced-motion` では止める。動きの種類は増やさない(縫う・染みるの 2 つのまま)。design.md の「動き」に足す

## 5. 見ていないこと

- 読み上げとキーボード(復習で答えたあとのフォーカスの行き先、`details` の開閉の読み上げ)
- 復習で答えたあとの選択肢の札(撮影は解説の箱から下で、選んだ答えと正解が画面の外)。閉じた「予想したら、実行結果を見る」(m-sample-closed はコードの上端で、欄が写っていない)
- 新しい画面の暗い表示(復習・実行結果)と、PC のサンプル・実行結果
- 復習の読解・演習の型、「今日 n 問済み」の出方、卒業したとき
- オフラインの動作(`scripts/offline-check.mjs` は回していない)
- 教材全体の実行(サンプル・演習の出力が実行と合うか)。画面に出た範囲と読んだソースだけで判断
- 文字の大きさ・余白・1 行の字数は、2 倍の JPEG から目で測った値
