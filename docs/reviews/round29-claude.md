## 4. SOTD に届かない理由(効き目の大きい順)

Execute Program・Scrimba・Josh W. Comeau のコースと並べると、今回で PC の「書いた → 採点 → 染まる」がその場で応えるようになった。本文の画面の署名(布・運針・玉結び)と、間違えたあとの道(読み違えの 1 文 → のぞき見 → 仮縫い)は、この道場の方が上。残って負けるのは、**書く場面の細部**。相手の課題の画面では、指示が編集欄の外に出ることはなく、エラーのメッセージは最後まで読める。この道場では、演習の TODO の指示が右で切れる。サンプルの「ここを変えてみよう」で起こした NPE も、肝心の所で切れる。もう 1 つ、各段を読み終える瞬間に、玉結びが次の段の名前の横に座る。1〜3 を直せば、Design と Usability にも 9.0 が見える。

### 1. 書く場面のコードの幅: 演習の TODO の指示が右で切れ、1024〜1279px では張り出しが無い
- 軸・項目: Design D3、学びやすさ L4(Usability U3 の細かい所)
- 画面:
  - 撮り足し m1280-exercise-todo(java-exceptions の演習。11・13・17・18 行目の TODO が右で切れる)
  - m1200-sample(1200px。列 736px、左右に 232px ずつ空き、java-if の「// ここを変えてみよう:…」が切れる)
- 問題:
  - 演習の編集欄は、1440px で 40 / 135、1280px で 73 / 135 が横に送られる。切れる行の 3 分の 2 はコメントで、TODO などの指示の行が 1440px で 28 本、1280px で 54 本ある。書く人は、何を書くかを横に送って読む
  - 1024〜1279px は 28 回目に列を 736px にしたまま、`--bleed` が `.has-rail`(1280px 以上)にしか掛からない。そのため 27 回目(860px)より悪い
- 直し方:

### 2. 段の終わりで、玉結びが次の段の名前の横に来る

### 3. 実行時例外の中身だけ朱の塗りで、メッセージが切れ、JShell の内部名が出る
