## 4. SOTD に届かない理由(効き目の大きい順)

Execute Program・Brilliant・Scrimba と並べると、読む画面の現在地(布・運針・玉結び)と、間違えたあとの扱い(読み違えの 1 文 → のぞき見 → 仮縫い → 本縫い)は、この道場の方が上。負けるのは **PC で手を動かした結果の見せ方**。ほかのサイトは課題を終えた瞬間に、地図・進み具合がその場で動いて応える。この道場の PC は、いちばん大きな節目(藍)で黙っている。しかも結果の箱だけが緑と朱の塗りで、そこだけ CI のログに見える。審査員は PC で最初の演習を解く。そのとき、署名の比喩が途切れるのを見る。

### 1. PC で演習を合格しても、染まり・軸・冒頭がその場で変わらない
- 軸・項目: Creativity C1、Usability U2(学びやすさ L5 の細かい所)
- 画面: 撮り足し y-last-grade(java-loops の演習 3 問目に合格した直後。軸の「演習」は破線の途中に玉結びのまま、緑の「合格」の箱だけ)と y-reload-top(開き直すと「演習(済み)」が糸になり、冒頭も「藍(演習もできた)」)。e-after-grade(1 問合格しても「演習」のまま。開き直すと「演習 1/3」)
- 問題: クイズの採点結果は `dyedTo` で「縹に染まった」と染み込みを出し、`htmx:afterSwap` で帯の `.step[href="#quiz"]` に `done` を付ける。そこから軸の MutationObserver が縫う。演習の採点結果(`fragments/exercise.html`)にはどちらも無い。帯の演習は n/全部も済みも書き換わらず、軸も冒頭の色見本も古いまま。design.md の「本文の軸」の節も、縫う段から演習と STS を外している
- 直し方:
  - `exercise.html` の採点結果に、`quizResult` と同じ `<p class="dyed-line">`(`dye-burst` で「藍に染まった(演習もできた)」)を、この提出で染まりが上がったときだけ出す(コントローラーで提出の前後の `status.dyeLevel()` を比べ、`dyedTo` を渡す)
  - `.grade-result` に `data-passed="2" data-total="3"` を付ける。`app.js` の `htmx:afterSwap` で、帯の `.step[href="#write"]` の `<small>` を「2/3」に書き換え、全部そろえば `done` を付ける(読解の `readingStep` と同じ形)。これで軸は描き直され、演習の目が縫われる。冒頭の `.lesson-swatch` の `dye-N` と名前も同じ所で上げる
  - STS の確認の四角が全部そろったときも、同じく帯の `#sts` に `done`
  - design.md の「縫う段」に演習・STS を足し、`review-shots.mjs` に「PC で演習を全部合格した直後の軸と採点結果」を 1 枚足す

### 2. PC の実行結果・採点結果が、緑と朱の大きな塗りの面
- 軸・項目: Design D2(D4・C3 の細かい所)
- 画面: 撮り足し x-run-result(褐の編集欄の真下に、青竹の塗りの箱と暗いコンソール)、y-last-grade(緑の塗りに緑の ✔ が 6 行)、x-grade-fail・x-grade-fail-dark(6 テスト分の高さの朱の塗り。暗い表示では錆色の大きな塊)
- 問題: `app.css` の `.run-result.status-ok` と `.grade-result.status-passed` が `--ok-soft`、不合格が `--ng-soft`(= `--shu-soft`)で塗る。`.tests .pass .mark` は `--ok`(緑)。スマホのサンプルの結果とクイズの解説は「`--surface-2` の面に左 3px の線(藍 / 朱)」で、大きな面は塗らない。PC の手を動かす場面だけが 3 つ目の色相と大きな朱の面を使う
- 直し方:
  - `.run-result`・`.grade-result` を `background: var(--surface-2); border-left: 3px solid var(--accent)` に、不合格・例外は `border-left-color: var(--shu)` にする。`--ok-soft`・`--ng-soft` の塗りは小さい札(`.pill`)だけに残す
  - 見出しの「✔ 合格」は藍の文字とアイコン、「✘ 不合格」は朱の文字。テストごとの ✔ は `--accent-ink`、✘ は `--shu`(正解は藍、の決まりにそろえる)
  - 合格の箱の頭に、クイズの合格の点と同じ刺し子の目(テストの数だけ。通った目は藍、落ちた目は空き)を並べる。何本目を落としたかが並びで分かり、採点も「縫う」の言葉になる
  - 撮影に pc-run-result と pc-grade-pass / pc-grade-fail(明るい・暗い表示)を足す

### 3. 軸が出るのは、PC の 1280px 以上で AI の欄が無いときだけ
- 軸・項目: Creativity C2(細かい所)、Design D4(細かい所)
- 画面: `lesson.html` は `aiAvailable` のとき `no-tutor` を外し、軸は作られない(AI のキーを設定した人、つまり README が勧める使い方では、27 回目と同じ帯のまま)。1024〜1279px も帯
- 問題: 学ぶ人がいちばん長く過ごす本文の画面で、署名が出るかどうかが、AI のキーの有無と窓の幅で変わる

### 5. 小さな食い違い(1 行ずつ)
- 編集欄で `to`・`this`・`var` が予約語の色 → `annotations` と同じ `MatchDecorator` で、module 宣言の外の文脈キーワード(`to|with|module|requires|exports|opens|uses|provides|transitive|open`)の `tok-keyword` を `tok-variableName` に付け替える。`this` は highlight.js と同じ扱いにそろえる
- 冒頭の説明の最後の行に 1〜2 字(spring-di「で。」など 3 / 55)→ `text-wrap: pretty` に頼らない。組んだあと最後の行が 3 字以下なら、終わりの 6 字を `white-space: nowrap` の span に包んで組み直す(`phraseWrap` と同じ場所で)
- AI が未設定のとき、採点結果の「AIに講評してもらう」「エラーをAIに翻訳してもらう」が押せない形で 2 つ並ぶ → 未設定なら出さず、節の頭の「AI は未設定です」の 1 行に任せる
- 「復習キュー: 1日後に復習」→「1 日後の復習に入りました」(ほかの画面の言い方にそろえる)
- 軸のフォーカスの輪が藍の布の上で 1.9:1 → `.rail-step:focus-visible .rail-stitch { box-shadow: inset 0 0 0 2px var(--kon-ink); }` を足し、布の上は藍白の輪にする
- 撮影の台本: m-home-long-title と「ホームの題が札からはみ出す」の数えを `open(mobileArg + "?r=" + id + "#/")`(検索部分を変えて読み込み直す)に直す。PC の復習の問いを撮るには、撮影の前に PC の記録へ今日が期日の問題を入れる
