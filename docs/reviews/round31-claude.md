  - 1024〜1279px は、いまの段の名前だけを玉結びの左に 12px で常に出す(ほかの段は札のまま)
  - 台本の「軸の不具合」の数えに、「1280px で段の名前が見える」を足す

### 2. スマホのコードの折り返しの残り
- 軸・項目: Design D5・Usability U3(細かい所)
- 画面:
  - 撮り足しの m-gap-java-lambda-stream: 35 行目は行番号の行が空で、続きに「// base = 200; // ← コメ / ントを外すと」。36 行目は「//(28 字の空白)下の / 行がコンパイルエラー」
  - 公式の m-sample-comment: 6 行目「//(22 字の空白)var でも count は」
- 問題:
  - `jaSpace` は「和字の直後の空白」だけを折り返しの候補に戻す。そのため、英字や「←」の後ろの空白でつながった長い塊(コメントアウトしたコード + 行末コメント)は、`overflow-wrap` が語の途中で割る
    - 語の途中の割れは、カタカナ 2・英字 10
  - 字下げの空白は折れるので、長い塊は丸ごと次の行へ送られ、番号の行が空になる(4 行)
  - PC でそろえるための 19〜28 字の空白が、スマホでは穴に見える(3 本)
  - 出力の帯は、`phraseLines` が末尾の改行で空の行を 1 つ作る
- 直し方:
  - `numberLines`(スマホ・PC 共通の形)で、行頭の字下げを改行しない空白にする。中身が番号の行から始まる
  - `jaSpace` に 3 つの候補を足す
    - 後ろが和字の空白
    - コメントの中の 2 つ目の `//` の前の空白
    - 「←」「→」の後ろの空白
  - 760px 以下では、コメントの中の 4 字以上の空白の連なりを 1 字に縮める。または教材の側で、3 本の続きのコメントを上の行の形に直す
  - `phraseLines` は `text.replace(/\n$/, "")` してから分ける
  - 台本の「語の途中で割れる」の数えに、カタカナ同士・英字同士と、番号の行が空の行を足す(目標 0)。design.md の「撮影の台本が … 数える」の文も合わせる

### 3. スマホで「読んだ」を押すと、フォーカスが落ちる
- 軸・項目: Usability U4(細かい所)
- 画面: スマホのレッスンの「読む」の終わり(撮り足しの java-arrays。`document.activeElement` が body)
- 問題: ボタンを `outerHTML` で置き換えるので、フォーカスの行き先が無くなる。「読了。次は下の仕事のコードを読んでみよう」も「甕覗きに染まった」も、読み上げに届かない
- 直し方: `bindLesson` の `read` の処理で、置き換えたあとの `.done` に `tabIndex = -1` を付けて `focus({ preventScroll: true })` する(PC の `htmx:afterSwap` と同じ形)。演習の「できた / まだ」も同じ形にする

## 5. ほかの SOTD の学習サイトと並べたとき、どこで負けるか

Execute Program・Scrimba・Josh W. Comeau のコース・Exercism と並べると、次で負ける。
- **スマホで動かせない**: 他のサイトはスマホのブラウザでコードを実行する。この道場のスマホは、PC で実行した控えを開くだけ。審査員の多くは最初にスマホで触る。予想のチップ(4 の 4)があれば、「押して確かめる」の手触りは補える
- **最初の 5 秒とレッスンの動き**: Josh W. Comeau は開いた瞬間から小さな驚きを重ねる。この道場の動きは「縫う」「染みる」の 2 種類に絞った誠実なもので、レッスンを開いた瞬間には何も起きない(4 の 4 の C4)
- **目次の名前が常に見えない幅がある**: Josh W. Comeau や Execute Program の横の目次は、どの幅でも名前が見える。1024〜1359px の細い軸は針目だけ(4 の 1)
- **PC のホームの下の半分**: 上の大きな札と地図に比べて、下の「直近 8 週間の稽古」は白いカードで、汎用のダッシュボードに戻る
- **バージョン**: 動いているのは Spring Boot 3.5(OSS のサポートは終了済み)。STS で作る練習用のプロジェクトは 4.x。教材は正直に書いているが、他の講座は最新の系列に追いついている(ユーザーの判断で 4.2 の正式版を待っている所なので、点には入れていない)

勝っている所:
- 藍の布の軸と運針で読み進めを見せる形
- 選んだ誤答に向けた 1 文から、読み直す・仮縫いへ進む間違えたあとの道
- 書いて落ちたときの例外の文。編集欄の行・変数名・ラムダの持ち主で返す
- どの幅でも横に送らずに読める雛形と模範解答

この 4 つは、並べた中でこの道場がいちばん上。
