## 4. SOTD に届かない理由(効き目の大きい順)

Brilliant や Execute Program と並べると、この道場は「問われる瞬間」と「間違えた瞬間」では並んだ。誤答ごとの 1 文の厚みでは勝っている。負けるのは、**間違えたあとにもう一度挑む場面が無い**こと、**1 日の終わりに自分の読み違いを振り返れない**こと、**予想させる場面の多くが空の掛け声**であること。1〜3 を直せば L は 9 に届き、C1 もさらに強くなる。4〜6 は Design と Content の「一部」を消す。

### 1. 間違えた問を、その日のうちにやり直せない
- 軸・項目: 学びやすさ L3・L2(L5)、Creativity C1
- 画面: m-review-answer(誤答のあとは「次は 1 日後」「次の復習へ」だけ)、m-review-break、c2-done(「間違えた 2 問は、明日もう一度出ます」と「ホームへ」だけ)、c2-pc-review-end
- 問題: 誤答のあと、解説を 1 回読んで次へ進み、同じ問に触れるのは明日。学習科学では、間違えた問はその場の解説だけでは定着せず、同じ日の少しあと(ほかの問を何問か挟んで)にもう一度思い出して正解するのがいちばん効く(続けて思い出す練習・successive relearning)。Duolingo はレッスンの最後に間違えた問を出し直し、Anki は失敗したカードを数分後に戻す。この道場は比喩まで用意しているのに(ほどけた)、縫い直す場面が無い
- 直し方:
  - 区切り(10 問ごと)と今日の終わりの主ボタンを、間違えた問があるときは「ほどけた 2 目を縫い直す(約 1 分)」にし、「続ける」「ホームへ」は副ボタンに。縫い直しは、選択肢の並びを別の種(`ref + "|" + today() + "|retry"`)で入れ替え、題と出どころは隠したまま 1 問ずつ出す
  - 縫い直しで正解しても予定は動かさない(明日 1 回目のまま。今日は「仮縫い」)。記録は `S.reviewLog[t].retry = { [ref]: ok }`
  - 運針では、× の目の上に仮縫い(藍を 55% に薄めた破線の糸、手を止めての枠と同じ線)を重ねる。字幕「仮縫いした。明日、本縫い」。design.md の「復習」に、縫い直し・仮縫いの線を足す
  - PC の `review.html` の区切りと終わりにも同じボタン(`/review?retry=1`)

### 2. 今日の終わりが「何を読み違えたか」を言わず、「読み直す」はレッスンの頭へ飛ぶ
- 軸・項目: 学びやすさ L3・L5、Usability U2・U4、Creativity C1
- 画面: c2-pc-review-end(3 行の 2 行目が「次のコードを実行したときの出力は?」「次のコードの出力はどれですか?」「次のコードの出力はどれ?」で、どれがどの問か分からない)、m-review-break(「次のコードを実行したときの出力は? in…」)、c2-done(「OrderService は MailSender(se…」)、c2-rr-wrong-lower(「出どころ: ループ(読み直す)」)
- 問題: 1 日の終わりの振り返りは、「どの問を」ではなく「どう読み違えたか」を思い出させると効く。教材には誤答ごとの 1 文が 1,662 個あるのに、終わりの画面は問いの書き出し(多くは同じ決まり文句)を 13px で 30 字出すだけ。「読み直す」は `#/lesson/<id>` でレッスンの頭に着き、27 分のレッスンのどこを読めばよいか分からない。今日卒業した問(褐に染まった)も、終わりの運針では普通の縫い目と見分けがつかない
- 直し方:
  - 答えたときに選んだ番号も残す: `log[t].refs[ref] = { ok, c: choice }`(PC は `ReviewService#todayTally` に同じ)。間違えた問題の行の 2 行目を、その誤答の why の「〜と読んだ」までにする(例「case 1 から順に実行すると読んだ」「do-while も先に条件を判定すると読んだ」)。文字は 14px、`--ink`
  - 「読み直す」は問いの出どころへ: 手を止めては `#/lesson/<id>` に `pendingSection` と同じ仕組みで `check-<n>` へ送り、着いた所の手を止めてを 1.2 秒だけ藍の枠で示す。クイズは本文の該当の `##`(lesson.yml の quiz に `from:` を足す。無ければクイズの段の問 n)、読解は読解の段の n 問目
  - 今日の終わりの運針で、卒業した目の右に褐のマス(16px、`--dye-4`、復習の字幕と同じ)を添え、見出しの下に「褐に染まった 2 問」を 1 行。終わりの画面の下半分は、この 2 つと「明日の復習 n 問(約 m 分)」で埋まる
  - 「出どころ: ループ(読み直す)」は行全体を 44px のリンクにする(`.review-source a { display: inline-flex; min-height: 44px; align-items: center }`)

### 3. 予想させる場面の 7 割が空の掛け声で、本文は 33 か所で予想の前に出力を見せる
- 軸・項目: 学びやすさ L1
- 画面: m-sample-closed(このサンプルには「予想: ② のコンテナ版でも、コンストラクタは呼ばれるだろうか」がある。149 本のうち 104 本は「予想したら、実行結果を見る」だけ)、c2-gate-java-operators-below(畳みの外の本文では、コードの行末のコメントに答え `// 合計: 12  ← 3 じゃない!` が同じ帯に並ぶ)
- 問題: 予想は、答えを 1 つ決めて(書くか選ぶかして)から見ると効く(生成効果・事前テストの効き目)。「予想したら」は決める場面を作らないので、ほとんどの人はそのまま開く。最初の 6 レッスン(java-hello〜java-arrays)のサンプル 24 本には、予想の問いが 1 本も無い。本文でコードの直後に出力を見せる 33 か所も、読み進めると答えが先に目に入る
- 直し方:
  - lesson.yml の samples に `predict:`(問い 1 行、40 字まで)と `predict_choices:`(2〜3 個)を足し、`ContentRepository` で「predict の無いサンプルは起動時エラー」。スマホは閉じた欄の上に問いと選択肢のチップ(高さ 44px)を出し、チップを押すと欄が開いて「予想どおり / 予想と違った」を 1 行出す(記録はしない)。「予想せずに見る」は細い文字リンクで残す
  - 本文の出力の印 ```` ```text predict ````: スマホはサンプルと同じ閉じた欄「予想したら、出力を見る」、PC は開いた欄の上に 1 行の問い。java-variables・java-operators・java-if・java-loops の出力から(最初の章で「予想してから見る」癖をつける)
  - before の問いを、本文が「実行すると……」で引っ張る所(この型は 33 か所の多く)に足す。目安は各レッスン 1 問

### 4. 答えの前の問いは、答えると同じ説明を 3 回読み、「先に読む」はフォーカスを失う
- 軸・項目: Content N4、学びやすさ L4、Usability U4
- 画面: c2-gate-java-if-answered → c2-gate-java-if-opened(why「一番近い if に付く」→ 解説「else は一番近い if (x > 10) に結びつく。x は 7 なので…『5 以下』が出る」→ 開いた本文「インデントだけ見ると…実行すると……」「5以下」「x は 7 なのに『5以下』と出ました。Java の仕様では else は直前の(一番近い)if に結びつく」)
- 問題: 畳みは「答えてから本文で確かめる」ための仕組みなのに、問いの解説が本文の種明かしを先にしてしまう。同じ規則を 3 回読むのは負荷(重複の効果)で、本文の「実行すると……」の引きも死ぬ。加えて「先に読む」はボタンごと消えるので、キーボードと読み上げではフォーカスが `<body>` に落ちる。読み直しのたびに畳み直すのも、復習から「読み直す」で来た人には手間
- 直し方:
  - checks.yml で before を持つ問いは、`explanation` を本文に任せる 1 行にする(「続きの実行結果で確かめよう」)。復習では本文が無いので、復習だけに出す `review_explanation:` を持たせる(今の explanation をそこへ移す)。`ContentRepository` で「before の問いの explanation は 40 字まで」
  - `openGate` で `gate.tabIndex = -1; gate.focus({ preventScroll: true })`(「先に読む」のとき)
  - 開いた畳みを覚える: `S.gates[lessonId] = [n, …]`。答えた問か開いた畳みは、読み直しでは開いたまま(PC は `localStorage`)
  - 畳んだ所に、何が畳まれているかの 1 行を残す(「ここに 3 段落と実行結果を畳んでいます」、14px、上下に刺し子の破線)。今は問いの枠の直後にモカの吹き出し(「波括弧を省略すると…」)が来て、何を飛ばしたか分からない(c2-gate-java-if)

### 6. Java の文字列と識別子が、地の文の書体で組まれて読み違えやすい
- 軸・項目: Design D1・D5、Content N4、Usability U3

  - 選択肢と解説では、本文から受け継いだ `overflow-wrap: anywhere` を `break-word` にする(`.choice > span, .explanation, .check-why { overflow-wrap: break-word; }`)。1 行に収まる識別子は語の途中で折らない
