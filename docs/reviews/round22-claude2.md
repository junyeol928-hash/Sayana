## 4. SOTD に届かない理由(効き目の大きい順)

Brilliant や Execute Program と並べると、間違えた瞬間の手応え(自分の誤答への 1 文・ほどける運針)と、1 日の終わりの振り返り(あなたの読み)は、もうこの道場が上。負けるのは、**新しく入れた解き直しと振り返りの「仕上げ」**と、**組版の最後の 1 段**。1〜4 はどれも小さな変更で、1〜3 で L2・U3・D1 の「一部」が消え、4 で D4 が消える。5〜6 は L を 9 に上げる余地。

### 1. 解き直しが、数分前と同じ選択肢の並びで、運針に跡を残さない
- 軸・項目: 学びやすさ L2・L3、Creativity C1、Design D2・D4
- 画面: b-retry-1(ループの問い。2 問目に誤答したときと同じ「0 3 6 9 / 0 1 2 … 9 / 3 6 9 / 0 3 6 9 12」の並び。`notes-m.txt` の RETRY1〜3 は 3 問とも same order = true)、m-review-retry、p-retry-1(PC も同じ種)、b-retry-end・p-retry-end
- 問題:
  - 解き直しは「正しい答えを自分で取り出す」から効く。並びが同じだと、数分前に「上から 1 つ目が正解だった」と見た位置で当たり、思い出す練習が位置の記憶にすり替わる
  - 解き直しで正解しても、終わりの運針は × のまま、間違えた問題の 3 行も同じ × のまま。どれが直って、どれがまだかが分からない。「縫う・ほどける」の比喩が、ここだけ途切れる
  - 札「解き直し · 予定は変わりません」と終わりの「解き直し」の札が朱(朱は不正解の色)。札のすぐ上の段落が同じことを言う(「ここでの答えは記録せず、明日の予定も変わりません」)。「まちがえた」と「間違えた」が同じ流れで混ざる
  - PC の終わりは「今日まちがえた 4 問を、解き直した」で、何問直せたかを言わない(スマホは言う)
- 直し方:
  - 並び: スマホは `const order = (n) => choiceOrder(n, ref + "|" + today() + (inRetry ? "|retry" : ""))`。さらに正解の位置が 1 回目と同じになったら 1 つずらす(`const a = choiceOrder(n, ref+"|"+today()); const o = choiceOrder(n, ref+"|"+today()+"|retry"); if (o.indexOf(ans) === a.indexOf(ans)) o.push(o.shift());`)。PC は `ReviewService.choiceOrder(item, n, "retry")` に塩を足す
  - 跡: `S.reviewLog[t].retry = { [ref]: ok }` を残し、`stitchRows` で解き直せた × に仮縫いの糸を重ねる(`.break-unshin i.miss.basted` に、手を止めての枠と同じ「藍を 55% に薄めた破線」を横に 1 本)。見出しの下に「仮縫い 2 / 3(明日、本縫い)」。間違えた問題の行の右上に「仮縫いできた」(藍の細い枠)か「まだ」(朱)
  - 色と文: `.retry-kind, .retry-tag { color: var(--accent-ink); border-color: var(--stitch-color); }`(朱は × だけ)。段落を消して札を 1 行に「解き直し · 記録しません(明日の予定はそのまま)」。表記は「間違えた」にそろえる
  - PC: 解き直しの採点で正解数を数えて(`?retry=n&ok=k`)、終わりに「4 問のうち 3 問を、正しく解き直せた(予定は明日のまま)」
  - design.md の「解き直し」に、別の並び・仮縫いの線・札の色を書き足す

### 2. 「あなたの読み」が画面でいちばん小さく弱い字で、コードの書体を落とす
- 軸・項目: Usability U3、学びやすさ L3、Design D1、Content N4
- 画面: b-break-real・b-done-real(「i + = 3 を i+ + と同じと読ん / だ答え」13px の薄い字)、m-review-done(「サイズの無い new int[]{4, / 5} を疑った答え」)、p-review-end(札 11px)
- 問題: 終わりの画面の主役は「どう読み違えたか」なのに、文字は 13px・`--ink-muted`・2 行で切れ、札は 11px。レッスン名(15px 太字)のほうが先に目に入る。`missedList` が why を `textContent` にするので、`i += 3` や `new int[]{4, 5}` が地の文の字体になり、演算子が「+ =」「+ +」と割れて見え、配列の初期化子は途中で折れる。もとの why も、165 件でコードの字句をコード書式にしていない
- 直し方:

  - 行の階層を入れ替える: 2 行目を `.missed-read { font-size: .9375rem; color: var(--ink); line-height: 1.6; -webkit-line-clamp: 3; }`、レッスン名は `.missed-body b { font-size: .8125rem; color: var(--ink-muted); }` の札に、「あなたの読み」の札は `.75rem`
  - 教材: why と選択肢のコードの字句を `` ` `` で包む(165 件。例 java-loops#0「`i += 3` を `i++` と同じと読んだ答え」)。`./mvnw test` に「why・choices のコードの外に `\w\(\)`・`\+\+`・`\+=`・`==`・`->`・`::` があれば落とす」を足す

### 3. 識別子が語の途中で折れる(Null / PointerException)
- 軸・項目: Design D1、Usability U3
- 画面: m-check・m-check-answer・m-check-why(本文の手を止めて。z-npe.png)、復習の同じ問い
- 問題: `softBreaks` が 20 字以上の英字すべての小文字→大文字の境目に `<wbr>` を入れる。ブラウザは、語が次の行に丸ごと収まるときも、その印で折る。21 回目は「、」の後ろで折れていたが、本文の欧文が Segoe UI になって幅が詰まり、1 行目に「Null」まで入るようになった。コードを読む道場で、例外名が「Null」と「PointerException」の 2 語に見える。design.md の「例外名のような長い英字は単語の途中で切らない」とも食い違う
- 直し方:

  - design.md の言うとおり、文の選択肢の中の例外名もコードの書体に(「Spring が無いので注入されず、`NullPointerException` になる」)。教材の選択肢で例外名を地の文に書いている所を `` ` `` で包む
