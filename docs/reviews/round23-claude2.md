- D1 書体: **一部**。長い識別子を語ごと次の行へ送る `.ident`(inline-block)が、直前の開き括弧を行末に取り残す(m-quiz-inline「というエラー(」/「NoUniqueBeanDefinitionException )で起動」。全レッスンの本文と開いた解説で 48 か所)。行頭禁則・行末禁則が inline-block の境で効かないため。解説の長いメッセージのブロックが括弧の中にあると「(STS では」/ ブロック /「)になる。」と文が 3 つに割れる(m-q2-after、8 か所)。よい所: `NullPointerException` は語の途中で折れない(m-check・m-check-answer・pc-check)、主ボタンの 2 段目は 14px・字間 .02em、終わりの行の `new int[]{4, 5}`・`toUpperCase()` はコードの書体のまま。細かい所: 小さい太字で欧文(Segoe UI Bold)だけ太く、和文(BIZ UDPGothic Bold)が細く見える(z-missed-lesson-weight.png「DI と IoC コンテナ」)
- D2 色: **一部**。仮縫いの破線が `--stitch-color`(= `--line`)で、地との差が約 1.4:1(暗い表示 1.6:1)。終わりの運針で解き直せた × の下の破線はほとんど見えず、× だけの目と見分けがつかない(m-retry-end-rows-zoom.png・m-review-retry-end)。design.md の「手を止めての枠と同じ破線」(`--st`、約 2.6:1)とも、「正しく解けたら藍の破線の糸」とも違う。解き直しの問いの上の仮縫いは、正解すると `currentColor` の濃い破線になるので、**同じ仮縫いが問いの画面では濃く、終わりの画面では淡い**。「仮縫いできた」の札の破線の枠も同じ淡い色で、暗い表示ではほぼ消える(m-retry-end-dark)。朱が × と「まだ」だけになったのはよい。暗い表示の染めの順(見送り)は 22 回目のまま
