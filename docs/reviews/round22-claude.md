- m-review-break は、台本(`review-shots.mjs` 149 行目)が `reviewLog` に `refs` だけを書き `choices` を入れていないので、間違えた問題の行が前の形(「次のコードを実行したときの出力は? int x = 3; i…」)で写った。本物の流れでは区切りも「あなたの読み」になる(a-break-real)。台本の 149 行目に、終わりの画面と同じ `choices` を足すとそろう
- m-review-retry は、その日に答えていない問題が出る作りなので、「さっき見た並びと同じ」が撮影では見えない。台本で区切りの前に同じ問題を誤答してから解き直しへ進めると写る
- 撮り足しのヘッダーの「保存中」は、新しいプロファイルで保存が終わる前に撮ったため(製品の不具合ではない)

## 4. SOTD に届かない理由(効き目の大きい順)

Brilliant・Execute Program・Duolingo と並べたとき、「間違えた瞬間」と「1 日の終わりの振り返り」の厚みはこの道場が上になった。負けるのは、**新しく足した解き直しが位置の記憶で解けてしまう**こと(Duolingo は出し直しで並びを変える)、**読解の追跡と地の文の識別子に組版の粗が残る**こと、**毎日いちばん開くスマホの復習が、1 問ごとに上の 3 割を前置きに使う**こと。1 と 2 を直せば L2 と D5 の「一部」が消え、L は 9、Design は 9 に近づく。
