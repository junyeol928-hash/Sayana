## 4. SOTD に届かない理由(効き目の大きい順)

Brilliant や Execute Program と並べたとき、間違えた瞬間の手応え(自分の誤答に向けた 1 文・ほどける運針)は、もうこの道場のほうが上。負けるのは **組版の地力** と **振り返りの具体さ**。審査員の多くは Windows か Mac で開く。Windows では本文の英字が下で欠けて見え、それだけで「仕上げが甘い」と読まれる。1 日の終わりの振り返りは形はできたが、「何を間違えたか」を言わない。上の 3 件で Design の「一部」が 1 つまで減る。

### 1. Windows で、本文の欧文の下(g・j・p・q など)が欠ける
- 軸・項目: Design D5(D1)、Usability U3
- 画面: m-terms(「equals」「@EqualsAndHashCode」の q)、pc-glossary(「equals」)、m-reading(「javac」の j、「App」の p)、m-check-why(「Spring」の p・g)。拡大は `z-terms-equals.png`・`z-pc-equals.png`・`z-reading-q.png`・`z-body-g.png`。原因の切り分けは `z-fonts.png` / `z-fonts-400.png`(同じ Edge で、書体だけを変えて 56px で並べた。BIZ UDPGothic だけが太字でも並でも下が切れ、Yu Gothic UI と Meiryo は切れない。行の高さ 1.6〜1.85 でも切れるので、行の箱ではなく書体の描画の問題)
- 問題: 本文の `--font` は `"Hiragino Sans", "Hiragino Kaku Gothic ProN", "BIZ UDPGothic", …` で、Windows ではヒラギノが無いので BIZ UDPGothic になる。この組み合わせで欧文のディセンダが切れる。Java の学習サイトは地の文に英字(Spring・getBean・javac・equals・Repository)が多く、ほぼ全画面に出る。PC 版を開く週末の Windows がいちばん影響を受ける(iPhone はヒラギノ、Android は Noto なので出ない)。20 回目の撮影(m-terms)にも同じ欠けが写っていて、前からある
- 直し方:
  - いちばん安い: `--font` から `"BIZ UDPGothic"` を外し、`"Hiragino Sans", "Hiragino Kaku Gothic ProN", "Yu Gothic UI", "Meiryo", "Noto Sans JP", system-ui, sans-serif` にする
  - BIZ UDPGothic の仮名と漢字を残したいなら、欧文だけ別の書体から取る: `@font-face { font-family: "Dojo Latin"; src: local("Segoe UI"), local("Yu Gothic UI"); unicode-range: U+0020-007E, U+00A0-024F, U+2010-2027; }` を足し、`--font: "Hiragino Sans", "Hiragino Kaku Gothic ProN", "Dojo Latin", "BIZ UDPGothic", …`(Mac はヒラギノが先に当たるので変わらない)
