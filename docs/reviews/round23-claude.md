## 4. SOTD に届かない理由(効き目の大きい順)

Duolingo・Brilliant・Execute Program と並べたとき、「間違えたあと」の厚み(誤答への 1 文 → あなたの読み → 並びを変えた解き直しの仮縫い → 明日の本縫い)は、もうこの道場が上。負けるのは**組版の最後の詰め**で、特に今回の直しが生んだチップの割れは、読者の本題の Spring の章に出る。1・2 を直せば Design の「一部」が消えて 8.5、加重平均 8.60 で線を越える。3〜6 は数行ずつの直し。

### 1. 長い識別子の `inline-block` が、コードのチップの中で箱ごと割れる(今回の直しで新しく出た)
- 軸・項目: Design D5・D1、Usability U3
- 画面: m-ident-body・z-ident-table.png(spring-boot-startup の表で「`@` / SpringBoot / Configuration」と 3 行、「@」だけ前の行に残る。「`AnnotationConfigApplicationContext(A.` / `class,`(行の幅いっぱいの帯)/ `B.class)`」)、m-ident-quiz・e-retry2・z-ident-chip.png(spring-di のクイズ 2 問目の問いの文。復習と解き直しにも出る)
- 問題: `softBreaks` は `.choice span` と `:not(pre) > code` の両方に掛かり、20 字以上の英字を `<span class="ident">`(`display: inline-block; max-width: 100%`)で包む。地の文では狙いどおりだが、チップの中では、行より長い語が箱ごと次の行へ回り、箱の中で `<wbr>` で割れる。チップの地(`box-decoration-break: clone` の背景)は箱の最後の行の高さにしか塗られず、1 行目は地なし、2 行目は幅いっぱいの帯になる。`@` は文字の組に入っていないので、`@` だけ前の行に取り残される。チップの中の 32 字以上の連なりは教材全体で 62 か所、spring-boot-startup だけで 17 か所が 2 行以上に割れる
- 直し方:
  - `softBreaks` で、チップの中では包まない: `const inCode = n.parentElement?.closest("code");` を見て、`inCode` なら今までどおり `<wbr>` だけ(インラインのまま、`clone` で行ごとに地が付く)、そうでなければ `.ident`。または CSS で `:not(pre) > code .ident { display: inline; }`
  - 文字の組に `@` を入れる(`/[@A-Za-z0-9_.(,]{20,}/`)。`@SpringBootConfiguration` が 1 つの語として扱われ、`@` だけ残らない
  - 表のセルの中のチップは `<wbr>` の後ろでだけ折れればよいので、上の 2 つで足りる。review-shots に spring-boot-startup の表を足し、`.ident` の高さが 1 行を超える数(今 17)を記録に出す

### 2. 同じ問いの中で、出力の選択肢の書体が分かれる(17 問)
- 軸・項目: Design D4・D1、学びやすさ L2
- 画面: b-q2・z-choice-fonts-loops.png(java-loops のクイズ 1 問目: 「0 3 6 9」「0 1 2 … 9」「0 3 6 9 12」は本文の書体、「3 6 9」だけコードの書体)、m-choice-fonts・z-choice-fonts.png(java-collections のクイズ 3 問目: 「[Apple, banana, banana, cherry]」だけ本文の書体)、j-reading-trace(java-loops の読解 3 問目: 「00 01 02 … 22」は本文、「00 10 20」「00」はコード)
- 問題: 選択肢をコードの書体にする判定(`app.js` 2187 行、PC も 229 行)は「ASCII だけで、空白で区切った語が 3 つ以上なら本文の書体」。出力の文字列は長さで語の数が変わるので、同じ問いの中で書体が混ざる。出力を 1 字ずつ見比べる問いで、数字の幅と空白の幅が選択肢ごとに違い、1 つだけ形の違う選択肢が目立つ(当てる手がかりにもなる)。教材の側でも、読解 java-arrays@0 のように全部を `<code>` で書いた問いと、書いていない問いがある
- 直し方:
  - 判定を問いごとに: 選択肢の中で ASCII だけのものが 2 つ以上あれば、ASCII だけの選択肢は全部 `code-choice` に(`const asc = spans.filter((sp) => /^[!-~][ -~]*$/.test(sp.textContent.trim())); if (asc.length >= 2) asc.forEach((sp) => sp.classList.add("code-choice"));`)。英語の文の選択肢(「Hi, Taro」など)もコードの出力なので、それでよい
  - 教材の決まりに「出力を問う問いの選択肢は、出力をコード書式で書く」を足し、`CurriculumTest#proseRules` で「同じ問いの ASCII だけの選択肢の、コード書式の有無がそろっていない」を落とす(今 17 問)
