## 4. SOTD に届かない理由(効き目の大きい順)

Brilliant や Execute Program と並べたとき、この道場は「本文の中で問われる瞬間」では並んだ。負けるのは、**間違えたあとの 30 秒**と**その日の終わり**。間違えたときに自分の誤答に向けた 1 文が出るのは手を止めてだけで、毎日の復習の大半(クイズと読解)では長い解説から自分の誤答を探す。終わりの画面は汎用の吹き出しで、何を間違えたか、どこを読み直すかを言わない。上の 3 件で L の 2 つの「一部」と D4・D5 が消える。

### 1. 誤答への 1 文が手を止めてにしか無い。読解の復習は判定が一番下に落ちる
- 軸・項目: 学びやすさ L3、Usability U5、Design D4、Content N4
- 画面: m-quiz-inline(「先に登録した Smtp が注入される」を選んでも、解説は全員向けの 1 段落)、m-review-answer(ABC を選んでも ABC への 1 文が無い)、撮り足し `c2-review-reading-answer` / `-answer2`(読解の復習: 選択肢 → 「1 行ずつの追跡」の箱 → 解説 → 空の「× 不正解」の箱 → 出どころ)、`c2-if-before-wrong`(why と解説の重複)
- 問題: 復習に出る問題は、手を止めて 173・クイズ 275・読解 171。誤答への 1 文があるのは 28% だけ。読解の復習は `renderReview` が `.md` を判定の前へ動かすので、判定(と focus の行き先)が解説と追跡の下になる。読解の画面(`readingAnswerHtml`: 判定 → 解説 → 追跡)とも逆。why 324 文のうち 81 文は、直後の解説が同じ規則をもう一度言う
- 直し方:
  - lesson.yml の quiz と reading.yml に checks.yml と同じ `why`(choices と同じ数・同じ順、正解は "")を足し、`ContentRepository` の数の検査も同じにする。描画は `.check-why` と同じ部品(判定の直下に太字 1 文)。クイズ・読解・復習の 3 か所で同じ
  - 書く順: 復習に入るクイズ 275 問から。解説に「〇〇と思った人は」と既に書いてある誤答(java-arrays 問 1 の「1 になると思った人は、b = a で配列が複製されると勘違い」など)を抜き出すだけで多くが埋まる
  - 読解の復習は `out.querySelector(".q-explain").before(out.querySelector(".md"))` をやめ、判定 → why → 解説 → 追跡 の順に(読解の画面と同じ)。判定の箱に中身が無いときは箱にせず、`.q-mark` の 1 行だけにする
  - why は「どう読み違えたか」の前半だけにし(「インデントのとおりに `else` を外側の if に結びつけた答え。」)、規則の文は解説に任せる。`InsertChecksTest` に「why と explanation が 12 字以上同じなら落とす」を足す
  - 「出どころ: 条件分岐(読み直す)」は、問いが本文のどこから来たかへ飛ばす(手を止めては `#/lesson/java-if` ではなくその問いの位置 `check-2`、クイズはクイズの段の問 n)。行全体を 44px の副ボタンにする

### 2. 本文のコードを指す問いが、復習ではコード無しで出る
