Execute Program・Scrimba・Josh W. Comeau のコースと並べると、29 回目に負けていた「書く場面の細部」(指示が編集欄の外に出る・エラーが途中で切れる)は解けた。本文の署名と、間違えたあとの道は、この道場の方が上。合格の線は越えていて、残りは 9.5 へ上げるための細部。

### 1. 雛形のコードの行(メソッドの宣言・例の呼び出し)が 1280px で右に切れる
- 軸・項目: 学びやすさ L4・Usability U3(どちらも細かい所)
- 画面: 撮り足し pc1280-datetime-ex3(java-datetime の演習 3)
  - 21 行目の `public static LocalDate addBusinessDays(LocalDate start, int n, Set<LocalDate>` で `holidays) {` が切れる
  - 32・34 行目の `count(LocalDate.of(…), LocalDate.of(…` は 2 つ目の引数の途中で切れる
- 問題:
  - 1280px の演習の編集欄は 810px(82 列)。雛形で 82 列を超えるコードの行は 77 行あり、うち書く所のメソッドの宣言が 21 本(1440px でも 27 行・5 本)
  - TODO は読めるようになったが、「何を受け取るか」の引数の名前は横に送らないと見えない
  - 同じ雛形の 29〜30 行目の `Set.of(…)` はすでに引数で折ってあり、折る・折らないが混ざる
- 直し方:
  - `CurriculumTest#commentsFitEditor` の検査を、雛形のコードの行にも広げる(82 列。和字は 1.7 列、または一律 80 列)
  - 宣言は引数の前で改行して 8 字下げる(`addBusinessDays(` の後ろで改行し、次の行に `        LocalDate start, int n, Set<LocalDate> holidays) {`)
  - main の例の呼び出しは `var from = LocalDate.of(2024, 6, 3);` と変数に分けるか、29 行目と同じ形で折る
  - 模範解答の 68 行のコメントも同じ検査に入れる(提出の前から開けるので)
  - 撮影の台本の数えに「切れるコードの行(雛形の宣言)」を足す

### 2. 例外の 1 行目の朱が見た目の 1 行目で切れる・ラムダの中の名前と JDK の行
- 軸・項目: Design D2・学びやすさ L3(どちらも細かい所)
- 画面:
  - 公式 pc-run-exception と pc-run-exception-dark(1440px のプレイグラウンドで「because "input" is null」が 2 行目の白)
  - 撮り足し pc1280-sample-exception(1280px のサンプルで「is null」だけが白)
- 問題:
  - `pre.exception::first-line` は、折り返した見た目の 1 行目にしか効かない。design.md の「1 行目(例外の名前と理由)だけ朱」は文の 1 行目のことで、いちばん大事な「is null」が地の文字に戻る
  - プレイグラウンドでストリームの中で落とすと `at lambda$do_it$Aux$0(5行目)` と JShell の中の名前が残る。続く JDK の中の 5 行で 6 行の上限が埋まり、呼んだ 4 行目が出ない
  - トップレベルは「at (14行目)」と、名前の無い括弧になる
- 直し方:
  - `run.html` で例外の文を最初の改行で 2 つに分け、1 つ目を `<span class="ex-head">` にして朱にする(`th:with` で `substringBefore` / `substringAfter`)。`m/app.js` の `<pre class="exception">` も同じにし、`::first-line` はやめる
  - `JShellRunner.simplify` で、`lambda$do_it$Aux$N` を「ラムダ式」、`lambda$名前$N` を「名前 の中のラムダ式」にする
  - 編集欄のコードの行を先に出し、JDK の中の続く行は「… java.util.stream の中 5 行」の 1 行にまとめる
  - トップレベルは「at 14行目」にする
  - `JShellRunnerTest` にストリームの例を 1 件足す

### 3. 冒頭の要約で、英字・チップの直後の助詞が行頭に来る(7 / 55)
