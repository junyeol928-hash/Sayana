## 良いところ(3 つまで)
- **「藍の稽古着」が機能に結びついている。** 染まり具合、刺し子、部の名札に一貫性があり、汎用的な学習アプリから抜け出している。染み込みと縫い進む線も、コード上は学習の操作・位置に対応し、動きを減らす設定に配慮している。
- **前回の主要な修正は確認できる。** 合格済みクイズから「演習へ進む」導線、採点結果の縦位置、段一覧の背景分離、絞り込みの整列、PCの章見出しは改善。暗色の染まり具合も形で区別できており、明暗の順序だけを理由に再変更する必要はない。
- **地下鉄で読む用途への対応に根拠がある。** オフライン画像とログには図・読解・374語の表示が記録され、「電波なし・保存済み」も安心して使える表現。DI教材も問題提起→素のJava→コンテナ→実務コードへつながる。ただし、今回のオフライン評価は既存記録に基づき、実機での再検証ではない。

## 直すべきところ(重要な順に最大 10 個。各項目に「どこ(ファイル/画面)」「何が問題か」「どう直すか」)
1. **段一覧のシートが、小さい画面への対応を欠いている。**  
   **どこ:** `m-lesson-top`、`mobile/mobile.css` の `.step-menu ol`、`mobile/app.js:663–665`。  
   **問題:** 390×844では収まるが、一覧はボタンの下に絶対配置され、高さ制限・内部スクロールがない。低い画面や文字拡大で末尾が画面外へ出ると、縦スクロールで一覧自体が閉じる。背景を覆う見た目に対して、キーボード操作を背景から分離する処理もない。  
   **修正:** 表示領域内に収まる高さを設定し、一覧内をスクロール可能にする。シートとして扱うなら、背景の操作抑止と閉じた後のフォーカス復帰まで揃える。

2. **固定ナビ下のフェードが、コードを白くかすませている。**  
   **どこ:** `m-quiz-inline`、`pc-quiz`、`offline-lesson-figure`。`static/css/app.css:457`。  
   **問題:** 前回の「本文の切れ端」対策が、暗いコード面に白い光沢帯を作っている。閉じ括弧や行番号が途中で消え、マットな画面の中でこの部分だけ質感が異なる。  
   **修正:** 本文へ重ねる14pxのグラデーションを外し、不透明なナビ面と細い境界線で区切る。ジャンプ先の見切れはスクロール位置の余白で処理する。

3. **390px向けのコード表示修正が、CSSの後勝ちで一部無効になっている。**  
   **どこ:** `m-lesson-atwork`。`static/css/app.css:600–606` と `974–977`。  
   **問題:** 400px以下で指定した行頭余白38pxが44pxに、番号札の左位置8pxが4pxに上書きされる。「番号を端から離す」「1行の字数を増やす」という前回の修正が届いていない。添付画像でも札が左端に近い。  
   **修正:** 760px以下の基本指定の後に400px以下の差分を置く。文字をさらに小さくする前に、意図した余白が実際に適用される状態へ直す。

4. **追加で学習すると、卒業済みの色が戻る。**  
   **どこ:** ホームの染まり具合。`mobile/app.js:200–207`、`124–130`、`734–735`。  
   **問題:** 褐の判定に、そのレッスンで登録された全復習項目を使っている。卒業後に未回答の読解を1問解くと未卒業の復習が増え、褐から藍へ戻る。関数を抜き出した確認でも再現した。「積み重ねるほど深くなる」という中心の約束と食い違う。  
   **修正:** 染まりの達成記録と現在の復習残数を分ける。追加の読解は復習件数に反映し、獲得済みの染まりは維持する。卒業条件も画面で明示する。

5. **読解の採点後は、選択と解説が食い違う状態を作れる。**  
   **どこ:** 読解画面。`mobile/app.js:724–748` の `bindReading`。  
   **問題:** クイズでは採点後に回答を固定するが、読解ではラジオを変更でき、表示済みの正誤・解説が残る。同じアプリ内で答え合わせの操作規則が異なる。  
   **修正:** 読解も採点後は回答を固定し、「もう一度解く」で解除する。クイズと同じ「正解」「あなたの答え」のラベルを付け、見直し方を統一する。

6. **採点の刺し子が、問題別の結果と紛らわしい。**  
   **どこ:** `m-quiz-score`。`mobile/app.js:227–228` の `scoreStitches`。  
   **問題:** 問2を間違えた結果なのに、5本の目は先頭4本が藍、最後だけ灰色。問題数と同じ数の印なので、「問5が不正解」とも読める。現状は得点の重複表示にとどまる。  
   **修正:** 各問の実際の正誤を順番どおりに示す。問番号を確認でき、該当問題へ移動できる形にすれば、刺し子が見直しの道具にもなる。

7. **教材の見出しに、根拠の示されない断定的な数字がある。**  
   **どこ:** `content/03-spring/01-core/01-spring-di/lesson.yml:283`。「『Bean が見つからない』の9割はアノテーションの付け忘れ」。  
   **問題:** 本文に「9割」の根拠がなく、直後にはパッケージ配置など別の確認事項も並ぶ。初心者に原因の頻度を誤って覚えさせる表現で、教材の信頼感を下げる。  
   **修正:** 「Bean が見つからないとき、最初に確認する3点」へ変更する。頻度を断言するより、確認する順番と理由を伝える。
