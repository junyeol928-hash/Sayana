# デザイン — 藍の稽古着

Java道場(スマホ版 `m/` と PC版)の見た目の決めごと。手順は design-direction スキル(コンセプト → モチーフ → 最小のデザインシステム → 3 案比較 → 参考との差分 → 検品)。
レビューの記録は [design-review.md](design-review.md)、画像の出典は [image-credits.md](image-credits.md)。

## 1. 目的と読者

- 読者は 1 人: 仕事で Spring Boot のコードを読む必要がある社会人。平日は通勤のスマホで読み、週末と仕事前に PC で手を動かす。
- 見る距離と時間: スマホを手元で 5〜20 分。電波のない地下鉄でも開く。PC はエディタと並べて 1 時間。
- いちばん大事なのは「本文が読みやすい」「次に何をやるかが 1 秒で分かる」「どこまで身についたかが見える」の 3 つ。

## 2. コンセプト

**稽古を重ねるほど、色が深くなる。**

藍染めは、布を甕(かめ)に浸けて引き上げるたびに色が一段ずつ深くなる。生成り(きなり、染める前)→ 甕覗き(かめのぞき)→ 縹(はなだ)→ 藍 → 褐(かち、「勝ち」に通じる)。実際の藍染めでは藍と褐の間に紺もあるが、進み具合は 5 段で足りるので紺は段にせず、本文の文字の色(`--ink`)に使う。
1 回で深い色にはならず、繰り返した回数がそのまま色に残る。間隔をあけた復習で身につけるこの道場の仕組み(読む → クイズ → 演習 → 復習 1・3・7・14 日)と同じ形をしている。

比喩の候補(最初の 1 つは捨てる前提で比べた):
1. 珈琲(今までのモカ先輩の世界) — 誰でも最初に思いつく。茶色とカップの絵文字で、学習の進み具合とつながらない。**捨てた**
2. 設計図・IDE・計測 — 等幅フォントと方眼の「記録・計測」型。AI っぽさを避けようとして逃げ込む新しい型。**捨てた**
3. **藍の稽古着** — 道場の稽古着(剣道着・柔道着)は藍染めの刺し子。染めの段階が「進み具合」に、刺し子の縫い目が「区切りと進行」に、そのまま使える。**採用**

## 3. モチーフ(8 軸)

| 軸 | 言葉 |
|---|---|
| 素材 | 厚手の木綿に藍を重ねた稽古着と、白い刺し子糸。マットで反射がない |
| 光 | 道場の高窓から入る拡散光。影はほとんど落ちず、奥行きは「色の段」で出す |
| 配色の出どころ | 藍の染め段階(生成り・甕覗き・縹・藍・褐。紺は本文の文字)と、晒し木綿の白。印(しるし)として朱を 1 点 |
| 構図 | 稽古着の合わせのように、左に 1 本の軸を通す非対称。縦書きの名札(部の札)を左の軸に下げる |
| 情報の優先順位 | ①今日の稽古(次のレッスン)②本文 ③染まり具合(進捗)④その他 |
| 余白 | 畳の目のように 4px の刻み。区切りは罫ではなく、刺し子のランニングステッチと余白 |
| 書体の声 | 落ち着いた太めのゴシック。道場の札のように、見出しは大きく短く。コードは読みやすい等幅 |
| 動き | 布に藍が染み込むように、色が中心からじわっと広がって止まる。弾まない。速く始まってゆっくり止まる |

様式は「主: 日本の工芸(藍・刺し子)× 副: スイス的な左揃えの格子」。和の記号(明朝・金・和紙)は重ねない。

## 4. デザインシステム(定数)

### 色(役割 × 段)。由来: 藍の染め段階と晒し木綿
OKLCH の色相 H は 245(藍色 237 と紺色 263 の間)で全段そろえる。

| トークン | ライト | ダーク | 役割 |
|---|---|---|---|
| `--bg` | 晒し `oklch(.985 .004 245)` | 褐 `oklch(.17 .025 250)` | 地 |
| `--surface` | 白 `#fff` | `oklch(.215 .03 250)` | 面(本文・カード) |
| `--surface-2` | 藍白 `oklch(.955 .014 245)` | `oklch(.26 .035 250)` | 一段沈んだ面・図の箱 |
| `--line` | `oklch(.88 .015 245)` | `oklch(.34 .03 250)` | 飾りの罫・刺し子 |
| `--line-strong` | `oklch(.62 .03 245)` | `oklch(.55 .035 250)` | 操作部品の枠(3:1 以上) |
| `--ink` | 紺 `oklch(.24 .05 255)` | 藍白 `oklch(.95 .012 245)` | 本文(15:1 前後) |
| `--ink-muted` | `oklch(.45 .035 250)` | `oklch(.78 .02 245)` | 補助の文字(7:1 以上) |
| `--accent` | 藍 `oklch(.45 .11 245)` | 縹 `oklch(.74 .10 240)` | 主操作・リンク・選択 |
| `--accent-soft` | 甕覗き `oklch(.93 .035 230)` | `oklch(.30 .05 245)` | 主色の薄い面 |
| `--shu` | 朱 `oklch(.53 .17 35)` | `oklch(.72 .14 40)` | 印: 不正解・注意・地図の主役の印・復習の数 |
| `--ok` | 青竹 `oklch(.52 .10 165)` | `oklch(.78 .11 165)` | 正解(文字とアイコンで示す) |
| `--code-bg` | 褐 `oklch(.20 .035 255)` | `oklch(.13 .02 255)` | コードの地(両テーマとも暗い) |

**染まり具合(進捗)の 5 段** — この道場の署名。レッスンの状態を色の深さで表す。どの段にも文字の名前を添える(色だけで伝えない)。

| 段 | 名前 | 状態 | ライト | ダーク |
|---|---|---|---|---|
| 0 | 生成り | まだ | 塗らず、弱い色の刺し子の破線 `oklch(.72 .02 245)` | 破線 `oklch(.42 .03 250)` |
| 1 | 甕覗き(かめのぞき) | 読んだ | `oklch(.88 .045 225)` + 縁 `oklch(.62 .08 230)` | 沈んだ面 `oklch(.36 .05 234)` + 縁 `oklch(.66 .075 234)` |
| 2 | 縹(はなだ) | クイズ合格 | `oklch(.6 .11 240)` + 刺し子 1 本 | `oklch(.6 .09 230)` + 刺し子 1 本 |
| 3 | 藍(あい) | 演習もできた | `oklch(.45 .11 245)` + 刺し子 2 本 | `oklch(.58 .13 248)` + 刺し子 2 本 |
| 4 | 褐(かち) | 復習をすべて卒業 | `oklch(.24 .06 260)` + 四角の刺し子の目 | `oklch(.5 .11 256)` + 藍白の四角の目(面と 5.2:1) |

- 生成りを塗らないのは、空のマスがチェックボックスや申込用紙の欄に見えないようにするため(枠の実線は入力部品だけが使う)。
- 一度染まった段は戻さない(卒業のあとに読解を解いて復習が増えても、褐は褐のまま。復習の残りは復習の画面とバッジで見せる)。
- 暗い表示では、目を引く強さを深さの順にする。甕覗きは地に近い沈んだ面に縁だけ(明るさの順のまま暗くすると、浅い甕覗きがいちばん明るく目立った。8 回目の指摘)。ただし最初のご褒美なので、生成りと見分けられる明るさは残す(面 .36・縁 .66。11 回目の指摘)。縹から先は深いほど藍に寄って少しずつ沈む(明るさ .60 → .58 → .50、色相 230 → 248 → 256)。深いほど明るくすると「深い色」の比喩が崩れ(1 回目の指摘)、彩度を上げすぎると褐が藤色に転んで画面でいちばん鮮やかになる(9 回目の指摘)。褐と藍は四角の目と 2 本の目の形で見分ける。刺し子の目は暗い表示では地の色。褐の四角の目だけは藍白にして、仕上げた札として形の強さで目立たせる(沈めた面に地の色の目では、到達点がいちばん目立たなかった。10 回目の指摘)。マスは文字ではない図形なので、地 `#07101a` と 3:1 以上を下限にする(甕覗きの縁 6.23・縹 4.96・藍 4.50・褐 3.18。`scripts/color_check.py` で検算)。明るい表示の 1 段も地と近いので縁で 3:1 を取る。
- 染めの名前には読みをふりがなで添える(凡例・ヒーロー)。1 行で出す所は「縹(クイズ合格)」の形にそろえる(ヒーロー・レッスンのメタ行。凡例だけは二行組み)
- 2〜4 段には刺し子の目の**形**を入れる(1 本・2 本・四角)。目の数はマスの大きさによらず固定(縹は長い目 1 つ、藍は 2 つ。点線の繰り返しだと大きさで目の数が変わった)。色の差が分からない人にも、暗い表示でも、段の順序が形で読める。
- レッスン一覧の「まだ」は印を置かず幅だけ取る(短い線は欠けた値の「--」に見えた。印は甕覗きから。空の四角はチェックボックスに見えるので、四角は地図の中だけ)
- 凡例は 3 + 2 の格子(褐だけ取り残さない)。各項目はマスを左に置き、右に「名前(ふりがな)と数」「意味」の二行。スマホのホームでは「染まり方の見方」に畳み、見出しに 5 つの印を並べる(何も読んでいない最初だけ開く)。レッスン一覧の右には意味の文字(「演習もできた」など)を出す。
- 8 週間の稽古の図は「稽古した回数」なので、染まりの色ではなく `--accent` の濃さだけで描く(染まりの色は染まり具合の意味にだけ使う)。読解の難しさも同じ理由で、四角と藍は使わず、高さの違う 3 本の棒を弱い文字色で描く
- 復習の数のバッジは朱。文字は明るい表示で白、暗い表示で地の色(7.3:1)。

- 有彩色は 1 画面で藍と朱の 2 色相まで。朱の塗りは小さい印だけ(地図の主役の印・復習の数・不正解の印)。連続日数の数字は文字の色で、0 日のときは出さない(減点の表示にしない)、ヘッダーの「保存済み」の点は藍(緑の点は第 3 の色相になるので使わない)。
- `opacity` で文字を薄くしない。コントラストは `scripts/color_check.py` で検算する。

### 文字。由来: 道場の札(大きく短く)と、長文を読む教材
- 本文: `"Hiragino Sans", "Hiragino Kaku Gothic ProN", "BIZ UDPGothic", "Yu Gothic UI", "Noto Sans JP", system-ui, sans-serif`(端末の書体。長文を速く出す)
- 見出し(`--head`): **Zen Kaku Gothic New** の 700 と 900(SIL Open Font License 1.1)。h1・h2・ロゴ・ホームの大きな題・数字に使う。端正で太くでき、道場の札の「大きく短く」に合う。13 回目までは「Web フォントは使わない」としていたが、見出しが端末の書体のままだと、色見本のほかに顔がなかった(点数が伸びない原因の 1 つ)。Service Worker が全ファイルを先に取っておくので、オフラインでも同じ見た目になる
- 見出しの書体は、題(部・章・レッスン)と画面の漢字・かな・英数字だけに絞って同梱する(749 字、各 約 85KB)。作り方は `scripts/subset-heading-font.py`。題に新しい字が入ると `HeadingFontTest` が落ちるので、作り直す。置き場所は `static/css/fonts/`(PC は `/css/fonts/`、スマホ版は `m/fonts/`。どちらも app.css からの相対パスが同じ)
- 等幅: `"Cascadia Code", "SF Mono", Menlo, Consolas, "BIZ UDGothic", monospace`
- 本文 16px(スマホ 17px)/ 行間 1.85 / 字間 0.02em。見出しだけ `palt`。`line-break: strict`、`text-autospace: normal`、`font-synthesis: none`
- サイズの段(px): 12(注記の下限)・14・16(17)・20・24・32・44(ヒーロー)。見出しは本文の 2〜3 倍
- ウェイトは本文 400 と 700、見出しの書体 700 と 900。上下関係は大きさと余白で
- 縦書き(`writing-mode: vertical-rl`)は部の札と、顔の左の軸だけ。軸では数字を漢数字にする(「第3部」→「第三部」。横倒しの算用数字は読みにくい)

### 余白。由来: 畳の目(4px 刻み)
- 4・8・12・16・24・32・48・72・112。外側(節の間)> 内側(見出しと本文)> 部品の中
- スマホの左右は 20px(本文)、全幅の藍の面は端まで

### 角・影・線。由来: 布(角は少し丸い)と拡散光(影はほぼ無い)
- 角丸: 小 4px(印・チップ)、中 8px(ボタン・入力)、大 14px(面)。子は親以下
- 上のヘッダーは不透明(マットで透けない。下を流れるコードがにじまないように)
- 名札(モカ・ハル)は面の札(枠だけの形は押せる部品に見えるので使わない)
- 影は浮いているもの(下部ナビ・シート・トースト)だけ。2 層、色は紺寄り
- 区切りは刺し子: `--stitch`(線の長さ 9px・間 6px、太さ 2px、角は丸い)。罫線の代わりに節の区切りと進み具合に使う
- フォーカスは 3px の藍の輪(`outline-offset: 2px`)

### 動き。由来: 藍が布に染み込む
- 署名の動き「染み込み」: 状態が深まった瞬間だけ、**押したボタンのそば**で、古い色のマスの上に新しい色が中心から円く広がって止まる(28px、560ms、120ms 遅らせて始める、`cubic-bezier(.22,1,.36,1)`)。使うのは ①読了 ②クイズ合格 ③演習の「できた」の 3 か所だけ。文字でも「縹に染まった(クイズ合格)」と添える
- そのほかは 160ms の ease-out(色・下線)。押下は `scale(.97)` 120ms
- 縫い進む線: 段の並びの下端に薄い実線を 1 本引き、レッスン本体(最初の段の先頭〜最後の段の末尾)を読んだ割合だけ、藍の刺し子が見えていく。縫い目の長さは変えず、見える範囲(`clip-path`)だけ広げる(布を縫い進むのと同じで、目が伸び縮みしない)。見える端は目の切れ目(15px ごと)で止め、160ms の ease-out で進む(目の途中で切れた欠片を出さない)。深まったときは、ボタンのそばの四角とレッスンのメタ行の色見本を同じ 560ms で 1 回だけ染み込ませる。角は 3 種類まで: 錠剤の形は排他のトグルだけ、ボタン・入力・セレクトは 8px、カードは 14px
- 段の並びは今読んでいる段に `aria-current` と藍の下線を付け、横に並んだ中で見える位置まで送る
- スマホ(760px 以下)の段の並びは、横に並べると 2 段しか見えず切れ端が残るので、「7段中3 いまの段の名前 ⌄」の 1 つのボタンにまとめ(分数の形は「済んだ問の数」だけに使うので、位置は言葉で)、押すと全部の段(済みはレ点、途中は n/全部)が開く。右に「質問」の文字つきボタン(枠なし。段のボタンが主、質問は従)。開いた一覧は段の帯と同じ幅のシートにし、後ろの本文は幕で沈める。シートは画面の高さに収め、中でスクロールする。閉じたらフォーカスを段のボタンへ戻す。段の帯は不透明な面と下端の線で区切る(地の色から透明への帯を重ねると、暗いコードの面に白い光沢が出た)。本文の上に浮かせない。PC は全部の段が横に並ぶのでそのまま
- 段の順は染まりの順: 読む → 仕事のコード → サンプル → クイズ → 演習 → 読解 → STSで試す。読解は染まりの条件に入らない腕試しなので演習の後ろ(合格後の「次へ」とヒーローの「演習ができたら藍に」が同じ段を指すように。11 回目の指摘)。合格後の点は数字の横に刺し子の目でも見せる(問の順に、縫えた目は藍、空きは弱い色。何問目を落としたかが並びで分かる)。読解も答え合わせのあとは回答を固定し、「✓ 正解」「× あなたの答え」を付け、「もう一度解く」で解き直す(クイズと同じ規則)。段の名前はスマホと PC で同じで、ヒーローや染めの条件の言葉(クイズ・演習)とも同じ(スマホ版 app.js の `SECTION_LABEL` が元。PC も同じ表を持ち、前回の続きは段の名前を記録せず段の id から引く)。見出しだけ、できることに合わせて「サンプルを見る」(スマホ)/「サンプルを動かす」(PC)。見出しの番号は段の並びの位置(読むが 01)
- レッスン中は下のメニューのどれも選ばない(ホームを開いているわけではないので)
- 段の「済み」はレ点(縹のマスは「クイズ合格」と紛らわしいので使わない)。まだの段は小さな点(四角にするとチェックボックスに見える)。仕事のコード・サンプルは、段が画面に 3 秒以上あって終わりが画面の中に見えたら済み(飛び越しただけでは付けない)。読解・書くは全問そろって済み、途中は「1/3」。パソコンでしかできない段(STSで試す)には「PC」の札
- 採点で選んだ誤答には朱で「× あなたの答え」、正解には藍で「✓ 正解」を、どちらも目に見える 14px の文字で付ける(色だけに頼らない。明るい屋外でも正解を解説まで読みに行かずに済むように)。ラジオも、正解は藍の丸にレ点、選んだ誤答は朱の枠に ×(塗らない)。いちばん強い記号を正解に置く。解説の箱では正解の全文を繰り返さない
- 解説の中の長いメッセージ・出力(24 字以上で空白を含むインラインコード)は、文の中のチップにせず、左に藍の細線の 1 ブロックにする(検索窓に貼る文なので途切れさせない)
- 採点の色: 大きな面は塗らない。解説の箱は `--surface-2` に左 3px の線(正解は藍、不正解は朱)と「× 不正解」の文字・アイコン。正解の選択肢は藍の枠、選んだ誤答は朱の枠だけ(朱の塗りは小さい印だけ、の決まりどおり)
- 採点の言葉は事実だけ(「満点」「合格(4 問以上)」「あと 1 問で合格(4 問以上)」)。藍への近道は次の一手の下に、藍のマスを添えた独立の一行のリンク(「演習ができたら藍に → 演習へ」)
- 段の一覧は、いまの段に藍の左線と面(レ点とは別の印)。外側を押す・Esc・縦スクロール・項目を選ぶと閉じる
- 段の並びの「n/全部」は済んだ問の数だけに使い、0 のときは出さない(クイズの最高点は冒頭の「クイズ最高」)。PC の読解もこのブラウザの記録で n/全部 とレ点。PC の見出しにも段の番号
- クイズは回答欄にそのまま正誤と解説を出し、結果の欄は点数・染まり(この採点で段が変わったときだけ)・間違えた問へのリンク・次の一手だけ(スマホも PC も)。合格したら主ボタンは段の並びの次(読解へ / 演習へ)、藍への近道は一行(「演習ができたら藍に」)。採点後は答えを止め、「もう一度解く」で元に戻す
- `prefers-reduced-motion: reduce` のときは JS のスクロールも即時にする
- `prefers-reduced-motion: reduce` ではすべて止める

### 下限(割らない)
- 本文 16px、補助 12px 以上。文字は 4.5:1 以上(大きい文字 3:1)。押せる所は 44×44px 以上
- 入力欄は 16px 以上(iOS の拡大を防ぐ)
- 絵文字をアイコンに使わない(1 セットの線のアイコンを inline SVG で、線 1.75px)

### コード
- 読解と「仕事のコード」は**横に流さず折り返す**。行番号を左に付け、説明のある行は番号を藍の札にして、行の背景を少し明るくする(下の「n 行」の説明と同じ番号)
- 折り返した行は行番号の列より右から始まるので、行の頭が見分けられる
- クイズの問題・答え・復習のコードも読むためのものなので折り返す
- 仕事のコードの説明はその行の直後に挟む(下の説明まで往復しない。スマホも PC も)。「説明をたたむ」でコードだけを通して読め、たたむと説明は下の一覧に出る(選んだ形は覚える)
- スマホのコードは 14px。深い字下げは 8 文字で止め、続きの行の始まりが右に寄りすぎないようにする
- 短い名前(3 文字以下)の直後の `.` では折り返さない(`q` と `.size()` が離れないように)。`//` コメントの中は折り返しの候補を入れず空白でも切らない(コメントの範囲を読ませる問題で、割れ方が答えに見えないように)。それでも収まらずに割れるときのため、コメントは薄い面で範囲を示し、折り返した続きの行には行番号の列に細い縦線を引く。行末の「 {」は前の語から離さない。400px 以下は字下げを半分にし、行番号の列を詰めて 1 行の字数を増やす(番号の札は画面の端から 8px 離す)。行の説明はコードの注なので、色を 1 段下げ、左の藍の線で従に見せる。大きさは下限の 14px を割らない(スマホはコード・説明・本文の例・サンプル・AI の回答のコードとも 14px。PC はコード 15px・説明 14px)。出力・識別子だけの選択肢(X3、IndexOutOfBoundsException)はコードの字体
- 例外名のような長い英字は単語の途中で切らない。`.` `(` `,` の後ろと、小文字→大文字の境目に折り返しの候補を入れる
- サンプルと演習、本文の例のコードは、書き写す・実行するものなので折り返さない(横にスクロール)

### 顔(ホームとレッスンの冒頭)。14 回目で作り直した
- 3 案(A 大きな札 / B 布の帳面 / C 名札掛け)からユーザーが **A 大きな札** を選んだ(撮影は `docs/screenshots/round14/face-*`)
- 左に藍の軸(稽古着の合わせ)を通し、部と章を縦書きで下げる。軸の布にだけ麻の葉の刺し子を薄く、右の縁に縫い目の破線。題は札の文字のように大きく太く(見出しの書体 900、字間を詰める)
- 題の大きさは長さで 3 段(`titleSize`。英数字は和字の半分の幅で数える): ホームはスマホ 56 / 42 / 32px、PC 96 / 68 / 50px。レッスンの冒頭はスマホ 42 / 34 / 28px、PC 52 / 40 / 32px。長い英単語(Repository など)が画面からはみ出さない大きさ
- 大きな題は語の途中で折らない(`phraseWrap`: Intl.Segmenter で語に分け、助詞・記号は前の語へ、開き括弧は次の語へつなぐ)。「コンテ/ナ」と折れていた。語の箱の切れ目では text-autospace が効かないので、和字と英数字が変わる所は前の箱の後ろに .22em 空ける。箱の中の空白は改行しない空白にする(端の空白が消えて「HelloWorld」になった)
- **運針(うんしん)**: 色に頼らない署名。レッスンの段を刺し子の針目で見せる。済んだ段は糸(実線)、主ボタンが指す段は糸の途中に朱の玉結び、まだの段は針穴(点)。下に「7 段のうち n 段済み / 次は 演習」。段の数はレッスンによって 5〜7。済みの判定はレッスン画面の段の並びと同じ(PC は記録にない「仕事のコードを読んだ」「読解を全問」をこのブラウザの記録から足す)
- PC のホームは上の帯に大きな札(左)と染まりの地図(右 400px)を並べ、下に記録(左)と一覧(右)の 2 列
- レッスンの冒頭は、部と章を軸に移し、現在地の文字列は読み上げ用に残す(見えるのは「ホーム」へのリンクだけ)

### ホーム
- 主役は「前回の続き」(最後まで読み切っていないレッスン。段と、段の先頭からの距離で覚えた位置まで戻る。画面を離れるときに位置を確定する)。読み切ったら次の新しいレッスン。一覧の札もヒーローと同じ言葉(前回の続き / 次の新しいレッスン)で、強調は主役の 1 行だけ
- 前回の続きのボタンは「クイズの続きから」(読むは「続きを読む」)。括弧書きのラベルは硬いので言葉でつなぐ。前回いた段がもう済んでいたら、主ボタンは次のまだの段(「演習へ進む」)にして「次:」の行と同じ段を指し、前回の位置へは副リンク「前回の位置(クイズ)へ戻る」で戻る。今日の復習は「なし · この先 n 問」、ある日は「n 問 約 n 分」(1 問 20 秒の目安)
- ヒーローは次の一手だけ: 所属・題・数・いまと次・主ボタン・「レッスン一覧へ」・今日の復習。次の新しいレッスンはヒーローに出さず、一覧の札と地図に任せる(スマホ。PC は横に余裕があるので、前回の続きのときだけ 1 行添える)。「ホーム画面に追加する方法」は箱にせず細い 1 行のリンクで、閉じられる
- PC は前回の続きをこのブラウザに覚え、ホームの主役を差し替える。差し替えるまでヒーローを隠す(ちらつかないように)
- 条件の文言はスマホと PC で同じ(「演習ができたら藍に」など)。PC のヒーローも染めの名前にふりがな、所属は「部・章」、補助の文字は 14px(1024px 以上)。PC のレッスン中は上のメニューに現在地を付けない
- ヒーローに、いまの染めの名前と次の段へ進む条件を 1 行で(「甕覗き(読んだ) クイズで 4 問以上取ると縹に」。条件は弱い色。PC も同じ)。PC の前回の続きでは先輩の一言も続きの話にする
- 保存の状態: 全部保存できたらヘッダーの小さな印(「保存済み」、藍の点)にし、電波がなくても全部保存してあれば「電波なし・保存済み」と藍の点のまま(地下鉄では想定どおりの状態なので警告にしない)。朱の「オフライン」は保存が欠けているときだけ。電波がない間は「質問」を弱い色にする。ヒーローの文は読み上げ用に残す。準備中・一部だけ・失敗のときだけヒーローに文で出す。Service Worker が制御していて、画面の部品と全レッスンがキャッシュにあるときだけ「保存済み」と言う。図は、描画に実際に読み込んだ部品(入口と分割された部品)の URL を覚え、全部がキャッシュにあるときだけ「図も保存済み」。欠けていれば取り直す
- 数字の欄は他の場所に出ない数だけ(次の復習・読解の正解・この 7 日の稽古)。今日の復習がある日は、ヒーローとバッジに出ている数を繰り返さず「復習で卒業」した問の数にする
- 染まり具合は部ごとの地図にする: 部ごとに 1 行、左に一〜四の札、章の切れ目はすき間。行を押すとその部の一覧へ(マス 1 つずつは押せる大きさが取れないので、行ごと押す)。折れるのは章の切れ目だけで、2 行目も同じ左端から。部の札の線は行の高さいっぱい。主役のレッスンのマスに朱の小さな印を付け、下に「前回の続き(今日の稽古)」と添える
- ホームに戻ったとき、前に見たときより深まったマスだけ染み込ませる
- 追加の案内は数字の欄の直下に詰め、第 1 部の前は 48px と刺し子の区切り(節の始まり)
- 図は狭い画面では縮めない(縮めると文字が 8px ほどになる)。14px のまま組み、はみ出す分は横スクロール。最初はノードの重心(中心の平均)が真ん中に来る位置から見せ、フェードは続きがある側にだけ付ける。図の下の「図の全体を見る」で、縮めた全体と行き来できる。図のラベルは教材の側で語の切れ目に `<br/>` を入れる。760px 以下はノードの間隔を詰める(nodeSpacing 20・rankSpacing 28)。枝が左右に出る図は、見えない線(`~~~`)で縦 1 列に積み、スマホの幅に収める。図の箱は角丸 8px、線は藍、判断の菱形は藍の薄い面(画面と同じ言葉)
- 横にはみ出す帯(段の並び・用語集の索引)のフェードも、はみ出しているときだけ出す(全部収まっているのにフェードがあると汚れに見える)
- 読む時間は本文から数える(文章 500 字・コード 12 行で 1 分)。手で書いた値は全部 15 分で、仮の数字に見えたため
- 図(Mermaid)には oklch() を渡さない(読めずに図ごと描けなくなる)。CSS の色は 1 点塗って #rrggbb に直して渡す
- オフラインの確認は `scripts/offline-check.mjs`(ヘッドレスの Edge で、保存されるのを待ってからネットワークを断ち、図のあるレッスン・読解・用語集を開いて撮る)

### 用語集
- どの語もレッスン名(「〇〇 で」)を説明の前に置く。いくつかのレッスンに出る語は 1 枚にまとめ、語の中のレッスンごとの説明は左の藍の細線でまとめる(カード同士の刺し子の区切りと分ける)
- PC の索引の線は本文の左右の端にそろえる(スマホは画面の端から端まで)
- 一覧は 1 列で上から順に読む。PC は語の名前を左(280px)、説明を右に分けた辞書の組み(格子だと短い語の下が空き、段組みだと読む順が画面の上下を往復した)。英字の語の読みはカタカナ。漢字の混ざる語は国語辞典と同じく、外来語の部分はカタカナ・漢字の部分はひらがな(「スローズせんげん」「カプセルか」)。全部をカタカナにすると和語まで外来語に見えるため。行の見出しは索引と同じ「A-Z」。用語集では索引の刺し子が区切りなので、ヘッダーの破線は引かない
- 行の索引は上に固定し、下端に 2px の刺し子の線と、地の色から透明への 16px の帯(本文が下に潜る境目)。行へ飛んでも語の名前が隠れないよう scroll-margin。「〇〇 で」の「で」はリンクの外。英字で始まる語(equals・@Bean など)は読みでなく「A-Z」に、綴りの順で。いま読んでいる行は藍の下線で示して見える位置へ送る。「n レッスン」は押せないので弱い色。先頭の虫めがねで検索欄へ戻る

## 6. 案内役の名前
- 案内役は「モカ先輩」と後輩の「ハル」。モカは前の珈琲の世界の名残だが、55 レッスンの会話がこの名前と口調で書かれていて、学習者もこの名前で読み慣れているので残した(名前を変えると、教材とこれまでのチューターの会話の記録がつながらなくなる)。見た目からは珈琲の記号(茶色・カップ・絵文字)を外し、藍の名札だけにしてある
