# デザインの相互レビュー記録

Claude と Codex が交互にレビューし、Awwwards の 4 項目(Design / Usability / Creativity / Content、各 10 点)で
**両方の採点が全項目 8.5 以上**になるまで直して回す。設計の意図は [design.md](design.md)。

- レビューの頼み方: 撮影(`docs/screenshots/roundN/`)と、ソース・`docs/design.md` を読んでもらう。同じ文面の依頼を両者に出す
- Claude 側は、作業している Claude とは別の Claude(サブエージェント。作業の経緯を知らない状態)が採点する
- Codex 側は `codex exec -s read-only` で、撮影を添付して採点する
- 撮影した端末は「視差効果を減らす」がオンのため、動きは止まった状態で写っている(採点者には CSS を読んで判断してもらった)

## 1 回目(撮影: `docs/screenshots/round1/`、全文: [reviews/round1-codex.md](reviews/round1-codex.md)・[reviews/round1-claude.md](reviews/round1-claude.md))

### 両者の主な指摘
- コードが横にはみ出して読めない(読解・仕事のコード)。PC は右の列が空いているのに横スクロール
- 中断したレッスンへ戻る道がない(ホームは未着手のレッスンを優先)
- 「質問する」が本文に重なる。PC は AI がオフでも右の 380px が案内で埋まる
- 「地下鉄でも読める」かがホームで分からない。図の描画部品が未取得だとオフラインで図が出ない
- 染まり具合のマスが小さいリンク(約 22px)。空のマスがチェックボックスに見える
- 段の並びに今の位置がない。後ろが透けて濁る。右端で切れて続きが分からない。縫い線が伸び縮みする
- 暗い表示で「深いほど明るい」と比喩が逆転。「読んだ」が地と約 2:1。「縹より深い」が条件と合わない
- ヒーローの刺し子が文字と競う。数字(復習・連続)が何度も出る
- 読解ページが 40 問までしか出ず、部・難しさで絞れない
- 用語集が平らで引きにくく、同じ語が別のカードに分かれる
- 署名の動き「染み込み」が操作した場所から見えない

### 直したこと(2 回目の前)
| 指摘 | 直し方 |
|---|---|
| コードの横スクロール | 読解と仕事のコードを行番号つきで折り返す。続きはその行の字下げ + 2 文字から。`.` の前・`(` `,` の後ろで折り返す。説明のある行は番号を藍の札に(スマホ・PC 共通) |
| 戻る道 | 最後に開いたレッスンと段を覚え、ホームの主役を「前回の続き」に。新しいレッスンは下に控えめに |
| 質問ボタン | 下へ読む間は隠し、戻ると出す。最後の行の下に余白。PC は AI がオフなら 1 列にして本文・コードに幅を回し、一行の案内だけ出す |
| オフライン | ホームに「全 55 レッスンをこの端末に保存済み」(各レッスンの JSON がキャッシュにあるかを数える)。電波のあるうちに図の部品(5 種類の図)を先に読み込む。ネットの表示はオフラインのときだけ |
| マス | 帯は表示だけ(押す場所は章ごとの行)。まだのマスは塗らず弱い破線。卒業には刺し子の目 |
| 段の並び | 不透明に。下の線は 1 本、読んだ割合だけ刺し子が見えていく(目の長さは変えない)。今の段に `aria-current` と下線、横に送る。右端にフェード。押せる高さ 44px |
| 暗い表示 | 彩度を段の軸に。全段が地と 3:1 以上(検算: 3.5 / 4.2 / 5.8 / 7.9)。集計は「クイズ合格以上」 |
| ヒーロー・数字 | 刺し子を右下に寄せ文字の背後を静かに。数字の欄は「復習まで卒業・読解の正解・この 7 日の稽古」に。連続 0 日は弱い色 |
| 読解ページ | 部・難しさで絞り込み、20 問ずつ「もっと見る」で 171 問すべてへ |
| 用語集 | 同じ語を 1 枚にまとめ(405 件 → 374 語)、レッスンごとの説明を並べる。行の索引を上に固定。リンクは 44px |
| 染み込み | 読了・クイズ合格・演習の「できた」の押した場所で、古い色の上に新しい色が広がる。「縹に染まった(クイズ合格)」と文字でも |
| 名前 | 「モカ先輩」を残す理由を design.md に書いた |

- ゴールは段の並びの下に畳み、初めて読むときだけ開く
- 撮影について: 画面内ブラウザは Service Worker を登録できなかったため、2 回目の撮影ではレッスンの JSON をキャッシュに手で入れて「保存済み」の表示を出した(表示の判定ロジックは同じ)。進み具合は撮影用に入れた値

## 2 回目(撮影: `docs/screenshots/round2/`、全文: [reviews/round2-codex.md](reviews/round2-codex.md)・[reviews/round2-claude.md](reviews/round2-claude.md))

### 両者の主な指摘
- 「質問する」がまだ本文を隠す(開いた直後・戻ったとき)
- クイズのコードが折り返されずカードからはみ出す。採点すると同じ問題を結果欄にもう一度並べる
- 「保存済み」の判定が甘い(Service Worker の制御・画面の部品・図を見ていない)。撮影の手作業のキャッシュは証明にならない
- 「続きから」が段の先頭に戻るだけで、読んでいた位置に戻らない。染まりが 3 以上のレッスンは続きの候補から外れる
- DI の教材で、説明とコードが合っていない(@Value の説明があるのにコードにない、OrderService が要求する部品が途中で変わる)
- 中間の段(読んだ・クイズ合格・演習)が色だけで区別されている。暗い表示で深い段ほど明るく見える。ホームで染めの名前が使われていない
- 段の「済み」が付かない段がある(仕事のコード・見る)。済みの印が縹で「クイズ合格」と紛らわしい。STS が説明なしの略語
- PC は前回の続きがなく、数字の欄・AI オフの案内がスマホとそろっていない。8 週間の図が卒業の色を使っている
- 下限割れ(11px の文字・40px のボタン・太さ 800)、インラインコードの背景のちぎれ、説明のある行の帯が右端まで届かない、動きを減らす設定が JS のスクロールに効いていない、暗い表示のバッジが 2.4:1

### 直したこと(3 回目の前)
| 指摘 | 直し方 |
|---|---|
| 質問ボタン | スマホは段の並び(sticky)の右端の 44px のボタンに。本文の上には何も浮かせない |
| クイズ | 回答欄にそのまま正誤と解説。結果欄は点数(と染まり)だけ。クイズ・答え・復習のコードも行番号つきで折り返す(PC も) |
| 保存済み | Service Worker が制御していて、画面の部品(index・JS・CSS・目次・読解・用語)と全レッスンがキャッシュにあるときだけ「保存済み」。図の部品の先読みは制御が始まってから。準備中は静かな色の点で正直に出す(画面内ブラウザでは Service Worker が使えないので、3 回目の撮影は「準備中」のまま) |
| 続きから | 読んでいた位置(スクロール位置)まで戻す。候補は染まりではなく「最後の前後リンクまで読んだか」で決める。PC もこのブラウザに覚えてダッシュボードの主役を「前回の続き」に |
| 教材の不一致 | DI の仕事のコードの導入から @Value を外し、本文の OrderService を OrderRepository と MailSender の両方を受け取る形にそろえた(図・コンテナの例も) |
| 段の形と名前 | 縹は刺し子 1 本、藍は 2 本、褐は四角の目。暗い表示は明るさをそろえ彩度で段を付ける(4.5〜5.8:1)。凡例は「名前 / 意味」の二段。ヒーローに「いま 甕覗き · クイズで 4 問以上取ると縹に」。レッスン一覧の右は意味の文字。ホームに戻ると深まったマスだけ染み込む |
| 段の済み | 仕事のコード・見るは段の最後まで読んだら済み。済みの印はレ点。「STSで試す」+「PC」の札 |
| PC | 数字の欄をスマホとそろえた(次の復習・読解の正解・この 7 日の稽古)。AI オフは一行の短い文だけ。8 週間の図は藍の濃さだけ |
| 細部 | 文字 12px・ボタン 44px・太さ 700 にそろえた。`box-decoration-break: clone`。説明のある行の帯を右端まで。行の札の色をそろえた。JS のスクロールも動きを減らす設定に従う。暗い表示のバッジは地の色の文字(7.3:1)。「ホーム画面に追加」は閉じられる |
