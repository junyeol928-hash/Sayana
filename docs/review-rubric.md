# 審査の決まった物差し(14 回目から)

13 回目までは、毎回まっさらな採点者に「最大 10 個」の指摘を頼んでいた。そのため毎回新しい小さな指摘(1px・端のそろい)が見つかり、点数は ±0.3 の範囲で揺れるだけだった(`design-review.md` の「点数が伸びない理由」)。14 回目からは、Claude と Codex の両方が同じ物差しで採点する。

## 進め方

1. 前の回の撮影と今回の撮影を**並べて**見る(何が良くなり、何が悪くなったか)
2. 下の 4 つの軸ごとに、項目を上から確かめ、「満たす / 一部 / 満たさない」を付ける
3. 点数は項目の結果から決める(下の「点の目安」)。項目にない理由で点を下げない
4. 指摘は「8.5 に届かない理由」だけを書く。数の上限も下限もない(届いていれば 0 個でよい)。1 つの指摘には、どの項目を満たさないか・どの画面か・直し方を書く
5. 1px・数 px の端のずれは、読む・押すのに困るときだけ指摘にする

## 点の目安(どの軸も同じ)

- **9 以上**: 項目をすべて満たし、ほかの学習サイトにない見せ方がある
- **8.5**: 項目をすべて満たす(一部が 1 つまで)。人に見せて恥ずかしくない
- **8**: 一部が 2〜3 つ、または満たさないが 1 つ
- **7.5 以下**: 満たさないが 2 つ以上

## Design(見た目の質)

- D1 書体: 見出しと本文の役割が書体と大きさで分かれ、見出しに顔がある。和文の詰め・行間が整っている
- D2 色: 色の役割(地・面・文字・主操作・印)が決まりどおりで、暗い表示でも同じ順に読める
- D3 余白: 外側 > 内側 > 部品の中 の順が守られ、詰まった所・余った所がない
- D4 一貫性: スマホと PC、ホームとレッスンで同じ部品が同じ形をしている
- D5 細部: 線・角・アイコンの太さがそろい、はみ出し・重なり・欠けがない

## Usability(使いやすさ)

- U1 次の一手: どの画面でも、次に押すものが 1 秒で分かる(主ボタンが 1 つ)
- U2 現在地: 自分がどこにいて、どこまで済んだかが分かる
- U3 読みやすさ: 本文・コード・図がスマホの幅で読める(文字 14px 以上、横スクロールは図とコードだけ)
- U4 操作: 押せる所は 44px 以上で、押せない所は押せそうに見えない。キーボードと読み上げでも使える
- U5 状態: 正解・不正解・保存・オフラインが、色だけでなく文字や形でも分かる

## Creativity(独自性)

- C1 コンセプト: 「稽古を重ねるほど、色が深くなる」がホーム・レッスン・採点で形になっている
- C2 署名: 色に頼らない署名の要素がある(顔の大きな札と軸、運針)
- C3 既視感: よくある学習サービスやテンプレート(カード 3 列・丸いバッジ・紫のグラデーション)に見えない
- C4 動き: 動きがモチーフ(藍が染み込む)から来ていて、多すぎない

## Content(教材の中身)

- N1 正しさ: コード・用語・バージョンの事実が正しく、動く
- N2 順序: 前の章で習っていないことを前提にしない。段の順が筋どおり
- N3 仕事とのつながり: 仕事のコードと読解が、読者の仕事の形をしている
- N4 文: 言い切りで短く、用語がそろっている。転載禁止の教材の文がない
